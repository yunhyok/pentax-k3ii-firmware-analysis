RAW 이후의 처리 경로와

RAW 작업 목록과 모듈별 처리 경로를 따라 톤 적용 및 저장 분기를 조사했다. selector=6은 메타데이터 변환을 거쳐 Reversal Film에 대응한다. WB와 색 행렬에서는 값의 출처, CPU 연산, 레지스터 기록을 원본 ARM 명령으로 대조했다.

후속 검증 반영: 이 보고서에 미확정으로 남긴 JPEG 버퍼 전달과 화면 메뉴 이벤트는 버퍼·메뉴 후속 보고서에서 추가로 연결했다. 아래 내용은 앞선 분석 단계의 근거를 보존한 기록이다.

코드 주소는 별도 표시가 없으면 해제 이미지의 파일 오프셋이다. 주 이미지의 분석용 VA는 파일 오프셋 + 0x02000000이다. 0x2002… 등은 명령이 사용하는 장치 주소다. 아래 도식의 화살표는 CPU의 호출·값 전달 관계를 나타내며, ISP 내부의 실제 픽셀 처리 순서를 뜻하지 않는다.

1. RAW 전달 뒤의 작업 처리

이전 분석에서 멈췄던 컨트롤러 호출 뒤로 작업 목록과 이벤트 대기 루프를 연결했다. RAW 작업을 만드는 함수 0x5A1618은 목록에 노드를 넣고 상태 1을 설정한다. 0x5A11F8은 상태 2를 쓰고, 작업자 0x6DCB14가 호출하는 0x5A12A4는 상태 2인 노드를 골라 상태 3으로 바꾼다. 컨트롤러와 RAW 보조 객체가 같은 목록 객체를 참조한다는 점도 생성 코드에서 확인했다.

색 처리 객체의 적용 함수 0x4BCD24는 상태 바이트에 따라 색 행렬 하위 객체 +0x164와 톤 하위 객체 +0x454를 각각 호출한다. 이는 두 설정을 공통으로 관리하는 소프트웨어 객체가 있음을 뒷받침한다. 두 블록의 실제 하드웨어 처리 순서나 동일 프레임의 완료 시점을 증명하는 근거는 아니다.

직접 근거: 작업·수신 객체·출력 연결, 톤 준비·적용, 색 행렬 적용.

원본 명령열 생성 함수 0x76E7AC에 작업 레시피 ID 0x0B–0x15를 넣어 11종을 비교했다. 메모리 할당 함수만 대체했고, 각 명령 배열의 128개 항목을 읽었다. 다음 세 레시피에는 RAW·톤·스케일러·저장 단계가 모두 들어 있다. 표의 숫자는 0부터 시작하는 명령 배열 위치이며, 레시피 ID는 다음 절의 톤 selector와 다른 번호 체계다.

표는 operation 5의 모듈 호출 위치다. 0x15에는 위치 16에 operation 6의 별도 톤 호출도 있다. 반면 0x14에는 위 두 종류의 톤 호출이 없다. 명령열의 배열 순서는 확인했지만, 실제 스레드와 장치의 모든 조건 분기가 완료되는 상황을 실행한 것은 아니다. 11종 명령열 결과

톤 수신부는 완료 메시지 0x00600003을 컨트롤러에 보낸다. 0x6DBF08 → 0x6DB9EC → 0x6DBCE0 경로는 해당 작업의 모듈 0 완료 상태를 기록하고, 조건에 따라 0x6DBE0C → 0x6DBD0C → 0x6DB894로 작업을 다시 제출한다. 따라서 톤 호출 뒤 컨트롤러로 돌아오는 연결까지 확인했다. 완료 콜백·재제출 근거

JPEG 압축과 파일 출력의 경계

후속 분석에서는 별도 JPEG 모듈 16의 버퍼 전달과 Exif 출력 어댑터를 확인했다. 아래 0x82B3C0의 일반 슬롯 대상은 0x744784이며, 이미지 데이터 쓰기가 아닌 저장 준비 명령이다. 정정·후속 근거

저장 모듈 9의 메시지 0x00800001은 StoreImage 진단을 가진 0x5A9704로 이어진다. 이 처리부의 조건부 호출 0x5A9840 → 0x5A6BE8까지 확인했다. JPEG 코덱은 별도로 찾았다. 0x53C104가 DC·AC 허프먼 테이블을 구성하고, 0x53C828이 이를 설정하며 0x200F0000 계열의 장치 주소를 사용한다. 저장·코덱 근거

StoreImage의 출력 객체는 초기화 코드를 따라 0x82B3C0까지 연결했다. 이 함수는 출력 대상을 선택한 뒤 가상 함수표 +0x6C로 전달한다. 그 이후의 실제 대상은 미확정이다. JPEG 코덱의 별도 모듈 8은 0x00C00003을 받지만, 위 11종 명령열에는 operation 5로 모듈 8을 직접 호출하는 항목이 없다. 이것이 JPEG 압축이 실행되지 않는다는 뜻은 아니며, 내부 호출이나 버퍼 전달 경로를 더 연결해야 한다. 출력 대상·코덱 경계

CExifJpegWriter의 0x7CD15C는 FF D8(SOI), FF E1(APP1), Exif\0\0를 준비한다. 0x7EB1C0 / 0x7EB200에는 출력 객체의 가상 함수 호출이 있다. 그러나 처리된 픽셀 버퍼가 압축기로 전달되고, 그 압축 결과가 이 작성기를 거쳐 SD 카드에 기록되는 전 구간을 아직 증명하지 못했다. 이번 결과는 RAW→톤의 작업 연결과 JPEG 양 끝의 구현 확인까지다. 확인한 호출과 미확정 연결

2. selector=6은 Reversal Film에 대응한다

후속 분석에서 화면 이벤트 0x01205010, 설정값 6, 펌웨어 자체의 Reversal Film 문자열 리소스를 직접 연결했다. 실제 메뉴 이벤트 검증

이름을 메뉴의 나열 순서에서 가져오지 않았다. 톤 분기 함수 0x4DDAB8은 설정 객체의 +0x44 값을 0x52671C로 읽어 6과 비교한다. 이 값은 저장된 설정 레코드의 +0x9C 바이트에서 전달된다. 별도의 메타데이터 함수도 같은 바이트를 읽으며, 태그 0x004F를 기록할 때 6을 7로 바꾼다. 이 변환은 디스패처부터 반워드 쓰기까지 원본 명령으로 실행해 확인했다. 바이트·호출·실행 근거

따라서 selector=6의 모드 이름은 리버설 필름(Reversal Film)으로 판단한다. 근거는 K-3 II 바이너리의 값 변환과 ExifTool의 Pentax ImageTone 정의를 대조한 결과다. Ricoh의 K-3 II 사양에도 이 Custom Image 모드가 있다. 카메라 화면의 글꼴·문자 리소스를 직접 해독한 결과는 아니며, 메뉴 선택 이벤트가 이 값을 쓰는 연결은 아직 확인하지 못했다.

3. WB 값의 출처와 채널 순서

설정 레코드의 게인은 +0, +2, +4, +6, 오프셋은 +8, +0xA, +0xC, +0xE에 반워드로 들어 있다. 채널 순서는 RR, GR, GB, BB다. 하드웨어 레지스터에는 RR/BB와 GR/GB를 각각 한 워드에 묶으므로, 레코드의 순서를 그대로 레지스터 순서로 읽으면 채널을 잘못 대응시킨다. WB getter·호출·진단 라벨 대조

별도 입력 경로 0x626468은 부모 객체 +0x36C의 레코드에서 +0x3A…+0x40 값을 읽고 5비트 우측 이동한 뒤 같은 적용 함수로 보낸다. 직접 경로 4건과 이동 경로 4건은 서로 다른 채널값·필드 경계·범위 밖 값을 넣어 확인했다. 각 사례에서 장치 주소를 대신한 메모리 4,096바이트 전체를 대조해 주변 비트 보존도 검사했다. WB 8건 실행 결과

이 수식은 CPU가 필드에 기록하는 값의 변환이다. 실제 WB 곱셈의 이진 소수점 위치, 광원 추정 알고리즘, 1배 게인의 장치 표현은 확정하지 않았다.

4. 색 행렬의 준비와 적용

CC0, CC1, YC는 각각 다른 설정 출처와 필드 폭을 사용한다. CC0는 부호 있는 반워드로 저장된 행렬들을 순차적으로 곱한다. 첫 행렬곱 뒤에는 조건에 따라 ROM 행렬을 한 번 더 곱하고, 이어 세 번째 입력 행렬을 곱한다. 그 결과를 게인으로 조정한 뒤 대각 성분을 다시 계산한다. 마지막에는 각 계수를 −2048…2047로 제한한다. CC1은 별도 포인터에서 9개 반워드를 복사한다. 명칭은 펌웨어의 진단 라벨을 따랐으며, 어느 행렬이 특정 색 공간 변환을 담당하는지는 이 결과만으로 정하지 않았다. 생산자·설정 포인터·레지스터 근거

6. 검증 범위와 재현 방법

대상은 기존과 같은 v1.12 해제 이미지이며 SHA-256은 1b87bf35b290e4b4e8910beb4055c34f97504b65e249ad65e5ccc0402bd14cfc다. 각 검증 스크립트는 먼저 이 전체 파일 해시와 길이를 확인한다. 가상 장치 주소에는 일반 RAM을 배치했으므로 실행 결과는 CPU 명령의 값 변환과 쓰기 범위를 증명하며, ISP의 프레임 처리 성공을 증명하지 않는다.

원본 명령 실행에는 Unicorn 2.1.4를 사용했다. 별도 Python 환경에 python -m pip install unicorn==2.1.4로 설치하면 수치 검증을 재현할 수 있다. 저장소의 CI는 펌웨어를 포함하지 않으며, 단위 테스트와 HTML·JSON의 공개 범위·링크·파일 식별 일관성을 검사한다. 로컬 원본 명령 실행과 공개 CI는 별개의 검증으로 구분했다.
