재구축·업데이트 안내

이 주제는 “펌웨어를 고쳐서 카메라에 다시 넣을 수 있는가”를 다룹니다. 파일을 다시 포장하는 방법, 카메라가 파일을 검사하고 옮겨 적는 절차, 원본 함수를 직접 만든 코드로 바꾸는 방법을 차례로 조사했습니다.

핵심 요약

  • 업데이트 파일의 포장 방식을 정확히 재현했습니다. 고치지 않고 다시 포장하면 배포 파일과 한 바이트도 다르지 않습니다.
  • 카메라의 업데이트 코드가 확인하는 것은 파일 길이, 모델값, 고정 표식, 덧셈 체크섬이었습니다. 조사한 구간에는 암호 서명 연산이 없었습니다.
  • 검사 뒤의 전송·기록 절차와 오류 처리, 그리고 함수 하나를 C로 다시 만들어 바꿔 끼우는 시험까지 진행했습니다.
  • 모든 결과는 PC의 에뮬레이터에서 얻었습니다. 수정한 펌웨어를 카메라에 설치한 적은 없습니다. 실제로 받아들여지고 부팅되는지는 확인하지 않았습니다.

한눈에 보기

펌웨어를 고쳐서 카메라에 넣으려면 아래 단계를 모두 지나야 합니다. 이 주제의 문서는 앞의 여섯 단계를 PC에서 확인했고, 마지막 단계는 실물 카메라가 필요해서 남겨 두었습니다.

배경 지식

세부 문서를 읽기 전에 알아 두면 좋은 개념입니다.

배포 파일과 공식 업데이트 절차

리코는 K-3 II 펌웨어 1.12를 fwdc230b.bin 파일로 배포합니다. 공식 안내대로 이 파일을 SD 카드 최상위 폴더에 넣고 MENU 버튼을 누른 채 전원을 켜면 카메라가 스스로 업데이트합니다. 안내는 도중에 전원이 꺼지면 카메라가 동작하지 않게 된다고 경고합니다. 이 연구가 실물 카메라에 수정본을 넣지 않는 이유입니다.

주 이미지와 보조 이미지

파일 안에는 이미지가 두 개 들어 있습니다. 16 MiB짜리 주 이미지는 카메라의 주 프로세서가 실행하는 ARM 코드와 리소스입니다. 60 KiB짜리 보조 이미지는 내용이 8비트 MCU용 코드로 보이며, 근거는 하드웨어 식별 문서에 있습니다. 두 이미지는 포장 방식도, 카메라가 옮겨 적는 방법도 다릅니다.

XOR 난독화와 덧셈 체크섬

배포 파일은 내용이 XOR로 가려져 있습니다. 키를 만드는 재료가 파일 안에 평문으로 들어 있으므로, 방법을 알면 누구나 풀고 다시 가릴 수 있습니다. 체크섬은 이미지 전체를 32비트씩 더한 합이 0이 되게 맞춘 숫자입니다. 전송 중에 생긴 손상은 잡아내지만, 누가 만든 파일인지는 보장하지 못합니다. 이 점이 암호 서명과 다릅니다.

메일박스: 두 실행 문맥이 주고받는 방법

업데이트 코드는 합계 계산이나 플래시 기록을 직접 하지 않고 다른 실행 문맥에 맡깁니다. 공유 메모리의 정해진 칸에 명령 번호와 인수를 적으면, 상대 코드가 읽어 처리한 뒤 결과를 응답 칸에 적습니다. 이 문서들은 이 방식을 메일박스라고 부릅니다. 상대 코드가 어느 CPU 코어에서 도는지는 밝히지 못했습니다.

NOR 플래시의 섹터

주 이미지가 저장되는 플래시 메모리는 내용을 고칠 때 섹터 전체를 지운 뒤 다시 써야 합니다. K-3 II의 업데이트 코드는 128 KiB를 한 섹터로 다룹니다. 그래서 기록은 “비교 → 지우기 → 프로그램 → 다시 비교”의 반복이 됩니다. 플래시에 써 넣는 명령 바이트는 널리 쓰이는 표준 명령 집합과 모양이 같았지만, 부품을 특정하지는 않았습니다.

“원본 코드 실행으로 확인”의 뜻

이 주제의 검증은 펌웨어에 들어 있는 ARM 기계어를 PC의 CPU 에뮬레이터(Unicorn)에서 실행하는 방식입니다. 계산과 판단은 원본 코드가 하지만, 메모리와 주변 장치는 연구자가 만들어 넣은 것입니다. 그래서 결과마다 “무엇을 실행했고 무엇을 넣어 주었는지”를 나눠 적었습니다.

호출 규약

함수를 새 코드로 바꿀 때는 레지스터 사용 약속을 지켜야 합니다. Arm의 표준 약속은 AAPCS32입니다. 그런데 원본 펌웨어의 호출자가 이 약속보다 더 많은 것을 가정하는 경우가 있었습니다. 세 번째 문서가 이 문제를 다룹니다.

읽는 순서

조사한 날짜순이 아니라 업데이트가 진행되는 순서로 읽으면 이해하기 쉽습니다.

  • 1단계

    무손실 재포장과 업데이트 검사

    고친 이미지를 카메라가 받는 파일로 되돌릴 수 있는가. 카메라는 파일에서 무엇을 검사하는가.

    무수정 재포장은 원본과 같았고, 검사는 길이·모델값·표식·덧셈 체크섬이었습니다.

  • 2단계

    업데이트 전송과 기록 오류

    검사를 통과한 이미지는 어떤 순서로 옮겨 적히고, 오류가 나면 어떻게 되는가.

    보조 이미지는 전송 뒤 다시 읽어 비교하고, 주 이미지는 섹터마다 기록 뒤 다시 비교합니다.

  • 3단계

    톤 보간 함수 C 재구현

    원본 함수를 직접 만든 코드로 바꿔 끼워도 원본 호출자가 그대로 동작하는가.

    64바이트 함수 하나에서 호출 2,304회와 출력 2,048개가 일치했습니다.

함께 읽으면 좋은 문서도 있습니다. 파일을 푸는 방법은 펌웨어 파일 구조와 복호화가, 업데이트가 건너뛰는 섹터의 내용은 보존 섹터의 설정 저장이 다룹니다.
