원본 명령 처리기가 만든 작업 목록을 같은 설정 객체의 갱신까지 연결했다. 별도 패킷 처리기에서는 공급자 선택과 블록 번호를 구분했다. 계산 결과·대기 반환값을 준비하거나 잠금 구간을 생략한 경계를 아래에 표시했다.

코드 주소는 해제 파일 오프셋, RAM 주소는 가상 주소다. 명령 객체는 합성 입력이며 실제 통신 도착이나 카메라 메뉴 이벤트를 재현한 것은 아니다. 도식의 점선은 별도로 준비하거나 건너뛴 실행 경계다.

1. 유형 2·하위 코드 4가 작업 목록을 만든다

원본 0x7B5954는 명령 객체의 +0x858·+0x859를 읽는다. 유형 2, 하위 코드 4이면 0x7B5A00·0x7B5A9C를 거쳐 0x7B4EB4로 들어간다. 이 함수는 서비스에서 설정 객체를 조회해 스택 +0x11C에 보관하고 입력 첫 워드로 작업 계획을 고른다. 아래 일곱 입력에서 요청 필드와 포인터를 대조했다. 하위 코드 7은 0x81을 반환했으며 작업 목록을 제출하지 않았다. 명령 분기·계획 7건·거부 대조

원본 0x632CD4가 포인터 목록 0x40바이트를 작업자 +0x28C로 복사한다. 요청 자체는 원래 계획 스택에 남으며 각 포인터가 그 주소를 가리키는지 확인했다. 요청 +0x14는 입력 워드에 0x1000을 더한 하위 16비트이고 계획 0의 두 번째·세 번째 요청만 +0x18이 1이다. 잠금 이후 원본 0x630DC4…0x630DD4에 값 2와 작업자 포인터를 주면 +0x380에 OR 저장하며 0x6366D0이 이 비트를 검사한다. 비트가 없는 대조에서는 작업 목록 호출을 건너뛰었다. 원본 복사·주소 별칭·작업자 플래그

2. 계산 결과의 유효 바이트와 완료 마스크를 구분한다

원본 작업자는 요청의 두 인덱스 워드를 8비트로 줄이고 같은 설정 객체를 조회한다. 계산을 건너뛰고 실제 스택 위치 +0xF8에 결과를 넣어 후속 호출자를 실행했다. 결과의 첫 바이트가 0이면 개수 setter 두 번을 생략하지만 길이 setter는 호출한다. 비제로이면 둘 다 갱신한다. 세 연결 사례에서 개수 유지, C만 무효화, 복구를 재현했으며 전체 ID 0x63·0x64 RAM도 대조했다. 별도 잘못된 요청 0x101/26은 1/26으로 줄었고 원본 setter의 인덱스 <26 조건이 26의 저장을 막았다. 이 요청은 앞의 계획이 생산한 값이 아니다. 결과 대조 3건과 별도 인덱스 경계

명령 호출자의 0x7B5128…0x7B5150은 준비한 대기 반환값이 0이어도 같은 설정으로 0x74ED98을 호출했다. 이어 명령 +4에 0x19, +8에 반환값을 기록했다. 다른 호출자의 0x635F4C 이후는 열 개의 비트표를 합친 값과 결과 마스크가 정확히 같아야 갱신한다. 0x3FF는 통과했지만 0x1FF와 0x7FF는 복원 함수 진입 직전으로 갔다. 이 대조는 앞선 계산과 복원 본문, 이후 플래시 저장을 실행하지 않았다. 서로 다른 두 갱신 조건

3. 공급자 선택과 레코드 블록 번호는 별개다

하위 코드공급자 선택전달
6 / 7입력 첫 워드 0x63 · 직접 선택쓰기 / 읽기

쓰기 호출자는 명령 +0xC를, 읽기 호출자는 +8을 패킷 인수로 넘긴다. 읽기 함수가 패킷 +4에서 블록 번호를 얻기 때문에 두 배치가 다르다. 직접·변환 선택에서 블록 0·1·31을 각각 왕복시켜 전체 레코드와 인접 RAM, 명령 응답과 남은 바이트를 대조했다. 반환 워드 수는 513·512·508이었다. 잘못된 직접 선택 0x66과 변환 입력 16은 쓰기·읽기 모두 정지점 0x83E434에서 상태 레지스터 R4가 0x83이었고 ID 0x63 함수에는 도달하지 않았다. 이는 공급자 선택 검사이며 블록 번호 검사와는 다르다. 왕복 6쌍과 공급자 거부 4건

별도로 하위 코드 10·변환 입력 3에 블록 번호 32를 주면 위 생략 경계를 통과한 경로에서 첫 저장 예정 주소가 0x80010010이 됐다. 0x72E08C 저장 명령 직전에 멈췄고 RAM은 바뀌지 않았다. 이 결과는 준비한 명령 객체와 생략한 잠금 조건 아래의 주소 계산을 보여 준다. 실제 통신 입력으로 그 상태에 도달할 수 있는지나 장치의 취약성은 확인하지 않았다. 저장 전 정지 대조와 한계

4. 재현 범위

실행 명령을 대체하지 않았지만 각 실험에는 명시한 시작 상태와 생략 구간이 있다. 명령 객체의 실제 생산자, 잠금·스케줄러·계산의 완료, 원격 전달과 실물 기록은 남아 있다. 이 명령의 선택값을 SuperResolution이나 일반 촬영 메뉴의 값으로 동일시하지 않는다. 설정 검사 바이트의 생산자와 RAM 적재·저장 준비는 별도 검증으로 연결된다.

python verify_preserved_dispatch.py decoded.bin --compare analysis/preserved-dispatch.json
