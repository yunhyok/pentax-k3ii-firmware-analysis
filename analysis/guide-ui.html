메뉴와 UI

메뉴·UI 안내

메뉴에서 항목을 고르고 확정하면 카메라는 화면을 바꾸고, 글자를 준비하고, 고른 값을 설정으로 기록합니다. 이 주제는 그 과정이 K-3 II 펌웨어 안에서 어떤 단계를 거치는지 색공간 메뉴와 RAW 형식 메뉴로 추적합니다.

핵심 요약

  • 메뉴 선택 하나가 지나가는 길을 여섯 단계로 나눴습니다. 버튼 입력 → 메뉴 알림 → 화면 전환 → 글자 준비 → RAM 설정 기록 → 설정 섹터 저장 요청입니다.
  • 가운데 네 단계는 이 주제의 세 문서가 원본 코드를 PC 에뮬레이터에서 실행해 확인했습니다. 마지막 단계는 “촬영 준비와 보존 레코드” 주제의 문서가 다룹니다.
  • 두 메뉴에서 같은 규칙을 확인했습니다. 고르는 것만으로는 설정이 바뀌지 않고 확정(적용) 동작이 RAM의 설정 두 곳에 기록합니다.
  • 단계들을 처음부터 끝까지 한 번에 실행하지는 않았습니다. 구간별로 실행했고 구간 사이는 값을 직접 넣어 이었습니다. 버튼 입력, LCD 표시, 플래시 기록은 확인하지 않았습니다.
  • 다른 기종의 UI를 옮겨 오는 작업은 하지 않았습니다. 그러려면 객체 구조, 그리기 코드, 버튼 대응을 맞춰야 하는데 모두 남아 있습니다.

한눈에 보기

메뉴 선택은 여섯 단계를 거칩니다. ②~⑥은 구간별로 확인했고 ①과 맨 아랫줄은 아직 확인하지 못했습니다.

단계무슨 일이 일어나는가다루는 문서
① 버튼 입력버튼 조작이 화면 객체가 받는 논리 동작 번호로 바뀝니다.없음 (미확인)

배경 지식

세 문서를 읽는 데 필요한 개념입니다. 번호와 필드 위치는 모두 K-3 II 펌웨어 1.12의 내부 값입니다.

두 메뉴의 공식 이름
Color Space는 사용자 설정 메뉴 C3의 20번 항목이고 선택지는 sRGB와 AdobeRGB입니다. RAW File Format은 촬영 메뉴 1의 Image Capture Settings 안에 있습니다. 선택지는 PEF와 DNG입니다(K-3 II 사용 설명서 20·26·37쪽). PEF는 PENTAX 고유의 RAW 형식이고 DNG는 Adobe가 규격을 공개한 RAW 형식입니다(미국 의회도서관의 DNG 설명).
화면, 위젯, 논리 동작
메뉴의 한 화면은 펌웨어에서 객체 하나이고 화면 ID를 가집니다. 화면 속 제목, 선택 항목, 도움말은 위젯이라는 32비트 번호로 구분됩니다. 설명서의 OK·MENU 버튼 조작은 펌웨어 안에서 작은 번호(논리 동작)로 화면 객체에 전달됩니다. 어느 버튼이 어느 번호인지는 확인하지 못했습니다.
임시값과 확정
화면 객체는 “지금 고른 값”을 임시값으로 들고 있습니다. 확정 동작이 와야 임시값이 설정으로 넘어갑니다.
설정 번호, 현재값과 미러, 뱅크
설정은 번호로 구분됩니다(색공간 0x15C, RAW 형식 0x97). 값은 RAM의 두 곳, 즉 설정 객체 안의 현재값과 별도 블록인 미러에 함께 기록됩니다. 같은 설정 번호의 값은 뱅크라는 구획마다 한 벌씩 있고 활성 인덱스가 쓸 뱅크를 정합니다.
알림, 레코드, 깨움 값
메뉴 항목이 새 화면을 열려면 앱 객체에 알림을 보냅니다. 앱 객체는 요청을 24바이트 레코드에 적어 두고 작업 루프가 깨움 값을 확인한 뒤 처리합니다.
글리프 코드와 언어 표
메뉴 문구는 글꼴 속 글자 번호(글리프 코드)의 나열로 저장되어 있습니다. 문구마다 언어별 데이터 주소를 모은 언어 표가 있습니다.
구간 실행
이 주제의 검증은 원본 ARM 코드를 Unicorn 에뮬레이터에 올려 함수나 구간 단위로 실행한 것입니다. 메모리 할당, 잠금, 알림 수신처럼 주변 기능은 검증용 코드로 대신했습니다. 카메라에서 실행한 것은 없습니다.

읽는 순서

쉬운 문서부터 놓았습니다. 사이트의 문서 목록 순서와는 다릅니다.

  • 1

    색공간 메뉴와 표시

    메뉴에서 고른 값은 언제 설정에 기록되는가?

    고르기는 임시값만 바꾸고 확정은 RAM 두 곳에 기록합니다. 8개 사례와 글자 5개, 선택 그림 2개를 확인했습니다.

  • 2

    RAW 형식 메뉴와 텍스트

    다른 메뉴도 같은 구조인가? 메뉴 글자는 어떻게 준비되는가?

    PEF·DNG 메뉴도 고르기와 적용이 나뉘어 있습니다. 이벤트 12건과 글리프 준비 12건을 확인했습니다.

  • 3

    색공간 메뉴 알림과 화면 전환

    메뉴 항목의 요청은 어떤 조건에서 새 화면으로 이어지는가?

    필터, 대기 레코드, 전환 함수를 거쳐 화면 메모리 할당 요청까지 실행했습니다. 가장 내부적인 내용입니다.

  • 이어서

    보존 섹터의 설정 저장

    RAM에 기록한 설정은 어떻게 플래시에 저장되는가?

    “촬영 준비와 보존 레코드” 주제의 문서입니다. 내용이 달라졌을 때만 반대쪽 섹터에 쓰기를 요청합니다.

다른 연구와의 관계

설정이 저장되는 곳

이 주제의 문서는 RAM의 현재값과 미러에 기록하는 데서 끝납니다. 미러가 플래시의 설정 섹터와 연결되는 과정은 보존 섹터의 설정 저장이 다룹니다. 그 문서는 색공간 설정과 RAW 형식 설정을 바꾼 뒤 저장 함수를 실행해, 섹터 쓰기 요청이 나오는 조건을 확인했습니다. 메뉴의 확정 동작에서 저장 함수까지 한 번에 이어 실행한 적은 없습니다.

다른 메뉴를 다룬 문서

“영상 처리와 저장 경로” 주제에도 메뉴를 추적한 문서가 둘 있습니다. 네 메뉴는 화면 객체에 이벤트를 전달하는 공통 진입점을 함께 씁니다.

세 기종의 UI 이식 연구

K-3 Mark III 저장소에는 K-3 III, K-3 II, Q7의 색공간 화면을 나란히 놓고 “한 화면을 옮기려면 무엇을 맞춰야 하는가”를 정리한 문서가 있습니다(UI 이식 설계). 이 주제의 색공간 문서들은 그 비교에서 K-3 II 쪽 근거로 쓰입니다. 리코의 메뉴 대비표도 두 기종의 색공간 항목과 RAW 파일 형식 항목을 서로 대응시킵니다(대비표 PDF 1·4쪽).

주의

K-3 III의 UI를 K-3 II에서 돌리려면 적어도 세 가지를 맞춰야 합니다. 첫째는 객체의 필드 배치와 함수 호출 방식(ABI)입니다. 둘째는 글자와 그림을 화면 버퍼에 그리는 코드(렌더러)입니다. 셋째는 버튼을 논리 동작으로 바꾸는 대응(입력 매핑)입니다. 이 가운데 어느 것도 아직 하지 않았습니다. 지금 있는 것은 기능 이름의 대응과, 각 기종에서 따로 확인한 고르기·확정 규칙뿐입니다. 이식한 화면을 실행한 적도, 펌웨어를 고친 적도 없습니다.
