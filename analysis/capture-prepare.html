촬영 준비의 입력 생산과
원본 함수 반환까지의 버퍼 보존

앞선 분할 실험에서 생략했던 중간 호출을 원본 코드로 실행했다. 같은 작업 객체에서 정책 입력을 생산하고, 별도 대조에서는 준비 함수가 호출자에게 반환할 때까지 포인터와 메모리의 변화를 확인했다. 실제 촬영 작업의 실행 이력은 검증 범위에 포함하지 않았다.

정책 본문연속 호출입력 생산활성 조건반환·버퍼 보존실행 범위

코드 주소는 해제 파일 오프셋이다. 컨텍스트는 같은 촬영 작업 객체이며 A·B·C는 앞선 정책 보고서의 입력 이름이다. 이 값의 물리 단위나 메뉴 이름은 아직 확정하지 않았다.

1. 첫 세 호출 뒤 분기하고, 통과하면 정책까지 여섯 호출이 이어진다

원본 가상 함수 표 0xA684E0을 컨텍스트에 연결했다. 앞부분 대조 21건은 종류 0~11의 기본 조건 12건과 입력을 바꾼 9건이다. 세 호출을 거친 뒤에도 종류 5·7·8·11은 정책 블록을 건너뛰었다. 별도 연속 대조 21건에서는 같은 객체로 아홉 호출에 모두 진입하고 정책이 반환하는 것을 확인했다. 호출 주소·슬롯·전체 실행 결과

이 결과는 앞선 분할 준비 실험에서 남겨 둔 중간 호출의 상태 보존 가정을 해당 입력들에서 해소한다. 종류 11과 Pixel Shift Resolution의 메뉴 연결은 별도 메뉴·수명 분석에 근거한다. 여기서는 작업 종류를 입력으로 주었으므로 메뉴 조작부터 준비 함수까지를 한 번에 실행한 것은 아니다.

2. 조회 키의 비트와 고정 미러가 정책 입력을 만든다

루트 리더는 원본 0x6EBF5C, 자식 리더는 0x6EAD78로 생성했다. 루트 키 0의 바이트가 0x09 또는 0x0C이면 +0x5F=1이 된다. 키 0x2F는 +0x322의 비트 1이며 +0x4F로 전달된다. 이 비트가 켜지면 설정 F1/F2의 0x12·0x34를 원본 0x82E6F4가 합쳐 +0x20B8=0x1234로 쓴다. 꺼진 대조에서는 두 필드 모두 0이었다. 리더 입력과 보존된 출력

A 생산 함수는 기본 배율 0x2000으로 시작한다. ID 8 조회 뒤의 0x73E760은 고정 RAM 0x4041F420을 돌려준다. 무효 마커에서는 기본 배율을 유지했고 유효 마커와 다음 halfword 0x4000을 준비하면 키 6=0x30의 A가 0x8000에서 0x10000으로 바뀌었다. 자식 키 0x22와 디버그 0x66 대조에서는 실제 표 인덱스 보정이 A의 차이를 만들었다. A 생산자 대조

정책의 강제 조건에 쓰이는 +0x20B6은 앞서 생산한 +0x20B8과 다른 필드다. 루트 키 0x2F와 설정 F5를 1로 두고 +0x20B8=0x1234가 유지되는 상태에서, 준비한 +0x20B6만 1에서 2로 바꾸자 표 조회에서 강제 결과 4로 전환됐다. +0x20B6의 상위 생산자까지 확인한 실험은 아니다. 두 halfword를 분리한 대조

3. 설정 0x95와 별도 임계표가 +0x3C를 만든다

설정 키 0x95는 이 객체 배치에서 +0x15ED에 있다. 값 0은 +0x60 경로를 켜며 B=0x44에서는 +0x3C=1, B=0x45에서는 0이 됐다. 값 1은 기본 대조에서 +0x3C/+0x60/+0x61을 모두 0으로 남겼다. 값 2는 +0x61을 켜고 원본 0x739A38의 별도 4×8 임계표를 호출했다. 설정별 입력·출력

임계표는 파일 0x9E6202에 있으며 정책의 7개 표와 다르다. A=0x2000, B=0x24에서 준비한 signed16 C 원값 599·600은 10으로 나눈 뒤 59·60이 되고 +0x3C가 0·1로 갈렸다. B=0x44의 임계값 셀은 0이어서 C 원값 32767에서도 꺼졌다. 반면 루트 키 0=9가 만든 별도 플래그를 전달하면 C 원값 −32768에서도 표 검사를 우회해 켜졌다. 디버그 0x25의 설정은 뒤의 0x26이 다시 해제했다. 임계값·0 셀·우회·디버그 우선순위

같은 준비 실행에서 A=0x8000, B=0, C=0, 설정 0x95=1이면 정책 표 결과는 4였다. 내부 작업 종류 0은 최종 +0x47…+0x4A=[1,1,1,1], 종류 6은 [0,0,0,1]을 만들었다. 앞서 주입했던 A와 강제 플래그 일부를 이번에는 원본 준비 코드가 만들었다. 이 실행을 픽셀 소비자나 JPEG 출력까지 이어 간 것은 아니다. 별도 정책→패킷→이미지 대조

별도 반환 대조는 원본 세 번째 리더 생성자 0x6EB764, 싱글턴 생성자 0x4D5F28을 추가로 실행했다. 싱글턴 초기화 가드와 RAM 0x4041D51C의 포인터 표를 준비하고 이번 입력에서 선택하는 12번 행의 바이트를 1로 두었다. 별도 원본 생성 구간에서 내장 레코드 여섯 개를 만들고 0x653D74…0x653DC8의 저장 명령으로 컨텍스트 +0xC2C4…+0xC2D8에 연결했다. 이 상태에서 내부 종류 0·6·11은 준비 함수의 실제 반환 명령까지 실행됐다. 반환 대조와 관찰 진입점

종류 0·6은 가상 호출 25개, 종류 11은 16개를 거쳤다. 종류 11은 앞선 정책 블록과 뒤의 슬롯 0x78을 건너뛴다. 이 대조에서 미리 넣은 +0x47…+0x4A의 0xA1·0xB2·0xC3·0xD4는 반환까지 남았다. 원본이 이 네 플래그를 0으로 초기화한 것이 아니다. 마지막 0x6554F4…0x655550 반복문은 포인터 여섯 개가 가리키는 객체의 +0x3F0/+0x3F2만 0으로 썼다. 각 레코드 전체 0x3FC바이트와 인접 대조값으로 바뀐 범위를 확인했다. 이 포인터들은 컨텍스트 +0xA850 안의 내부 주소이며 여섯 번의 별도 할당으로 생성되지 않았다. 반환 경로·정확한 변경 바이트 검사

생성 구간은 원본 호출 0x653BAC에서 시작해 0x5AA434 직전에 멈췄다. 원본 Thumb 배열 생성 보조 함수가 0x73DD60을 여섯 번 호출하는 부분까지 실행한 것이다. 뒤의 다른 컨테이너 필드 초기화는 할당·RTOS 의존 호출에 도달하므로 생략했다. 전체 컨테이너 생성자를 완료했다고 주장하지 않는다. 이후의 포인터 저장과 준비 함수는 별도 원본 구간으로 실행했다. 생성 경계·레코드 내부 주소

5. 고정 미러의 읽기와 공급자 등록은 구분한다

ID 8·9·0x62 조회는 빈 레지스트리에서 실행됐다. 뒤의 getter는 조회 결과와 무관하게 고정 RAM 주소를 반환하므로 이 실험이 공급자 등록을 입증하지는 않는다. ID 0x62 뒤의 0x73EF20은 0x40106980을 반환한다. 무효 마커는 짧은 경로를, 유효 마커와 B≥0x7C는 준비한 필드에서 태그를 만드는 경로를 실행했다. 루트 키 0=9를 더한 별도 대조에서는 +0x3D=1도 확인했다. 유효 마커와 낮은 B가 함께 들어가는 부동소수점 경로는 이번 범위 밖이다. 미러·태그·분기 대조
