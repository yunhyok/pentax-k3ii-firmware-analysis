PENTAX K-3 II · firmware 1.12 · 2026-11-08

원본과 같은 파일을 재포장하고,
수정 후보의 검사 경로를 실행했다

변경 없는 해제 이미지를 다시 포장하면 배포 파일과 바이트 단위로 일치한다. 메뉴 글자 한 바이트를 바꾼 후보는 원본 ARM의 복호화·모델 표식·체크섬 검사를 통과했다. 이 검증은 메모리에서 실행한 업데이트 검사의 일부이며 카메라에 설치하거나 부팅한 결과는 아니다.

초기 분석파일 구조원본 검사대조 사례재현남은 범위연구 상태

C 재컴파일 후속: 톤 보간 함수 하나를 C로 재구현한 빌드·원본 호출자 대조를 별도로 검증했다. 설치 파일 생성과 물리 수용은 포함하지 않는다.

명시한 코드 위치는 해제 이미지의 파일 오프셋이다. 코드 VA는 0x02000000 + 오프셋이며 0xC0001FD0 계열은 메모리 매핑 통신 주소다. K-3 III의 압축 컨테이너·주소·체크섬 규칙을 K-3 II에 적용하지 않았다.

1. 주 이미지와 보조 이미지의 포장은 다르다

배포 파일은 0x100F000바이트다. 앞의 16 MiB와 뒤의 0xF000바이트가 서로 다른 IV를 사용한다. 128바이트 블록의 고정 키 XOR을 두 번 적용하면 원래 바이트로 돌아온다. 원본 복호화 함수 0x8476CC를 전체 파일에 실행해 Python 해제 결과와 대조했다. 원본 복호화·재포장 근거 · 기존 해제 도구

영역변환 제외 헤더체크섬원본 검사
주 이미지 0…0x10000000x100…0x2000x1F0에 little-endian 32비트. 영역 전체 합은 00x84765C kind 0과 통신 명령 7
보조 이미지 0x1000000…0x100F0000x1000000…0x10000800x100007C에 big-endian 32비트. 영역 전체 합은 00x84765C kind 1. 명령 7은 생략

체크섬 필드를 0으로 놓고 해당 영역의 워드 합을 구한 뒤, 그 합의 2의 보수를 기록한다. 원본 필드 값은 주 이미지 0x9BA2E395, 보조 이미지 0x8B53905B다. 이 포장 단계에는 K-3 III와 같은 바깥쪽 압축 스트림이 없다. 내부 리소스까지 모두 비압축이라는 의미는 아니다. 영역·체크섬 구현

2. 명령 7의 결과를 원본 수신기가 계산한다

업데이트의 파일 크기 검사는 0x5D64DC부터 고정 길이를 확인한다. 호출 0x5D655C/0x5D6568은 두 이미지의 복호화로, 0x5D657C/0x5D6590은 모델·표식·체크섬 검사로 이어진다. 이 호출 관계를 바이트와 직접 분기로 대조했다. 전체 업데이트 함수의 장치 I/O는 실행하지 않았다. 검사 위치·분기·해시

헤더 검사 0x5D47D0는 기대 모델값과 반복 표식 0xA55A5AA5를 확인한다. 주 이미지에서는 0x5D4788 → 0x599FB8이 통신 명령 7을 보낸다. 같은 이미지의 수신 디스패처 0xDA078는 명령 7을 0xDA248의 덧셈 루프로 연결한다. 이 루프는 전달된 워드 수만큼 읽어 32비트 합을 반환한다. 따라서 확인한 명령 7은 추가적인 암호 서명 연산이 아니다. 송신기·수신기 실행 결과

별도의 검사 함수 0x84765C도 합이 0인지 확인한다. kind 1에서는 워드를 바이트 반전해 더한다. 저장된 체크섬이 0xFFFFFFFF이면 이 검사를 건너뛴다. 재포장 도구는 두 이미지 모두 계산 결과가 이 값이 되는 입력을 출력 전에 거부한다. 이 조건만으로 전체 검사 우회를 주장하지 않는다. 원본 명령 고정값과 실행 경계

독립 검토에서 초기 도구가 우연히 0xFFFFFFFF를 계산할 수 있는 경계 문제가 발견됐다. 체크섬 합이 0인 후보라도 이 값은 원본 검사 생략을 선택하므로 명시적 거부를 추가했다. 양쪽 바이트 순서의 회귀 검사와 실제 펌웨어 수정 입력으로 거부를 확인했다. 원본 검사기에 값 6종을 각각 넣은 12건에서는 0xFFFFFFFF만 잘못된 합을 수용했다. 해당 함수의 전체 명령 구간에는 이 외의 상수 생략 분기가 없으며, 전체 업데이트의 모든 검사를 조사했다는 의미는 아니다. sentinel_cases와 거부 사례

3. 검사 통과와 정상 실행은 다르다

대조 입력확인 결과해석
무수정 해제 이미지재포장 SHA-256이 원본과 동일. 원본 복호화·검사 통과무손실 왕복 변환 확인
Pixel Shift 영문 리소스 첫 글자 P → p0xE4C6D8 한 바이트 수정 후 체크섬 보정. 원본 검사 통과같은 길이 리소스 후보의 오프라인 검사. 실제 표시 미확인
보조 실행 코드 한 바이트를 의도적으로 손상체크섬 보정 후 같은 검사 통과체크섬 통과가 실행 코드의 정합성을 보장하지 않는 음성 대조
체크섬 보정 없이 데이터 한 바이트 변경주·보조 검사 모두 거부. 주 이미지 명령 7도 0이 아닌 합 반환결과값을 고정한 가짜 통과가 아님
모델 표식 5곳을 각각 손상원본 헤더 검사 거부고정 표식 검사 확인

입력 크기 변경, IV·모델·중간 표식 변경, 기존 출력 폴더 재사용은 도구가 거부한다. 공개 저장소에는 원본·수정 펌웨어가 없고 검증 코드와 해시·수치만 남긴다. 메뉴 문자열의 식별 근거는 앞선 Pixel Shift 메뉴 분석에 있다.

원본 SHA-256은 a33485f351019960192891ef69ddc5d4904ef9e298671d9d9955679e4c901a9a이다. 해제본은 1b87bf35b290e4b4e8910beb4055c34f97504b65e249ad65e5ccc0402bd14cfc이다. 이 두 버전에 검증 범위를 고정했다. XOR 해제 알고리즘의 기존 출처는 pentax-firmware-tool 고정 커밋이며 이번에는 실제 펌웨어 복호화 명령까지 대조했다.

5. 설치·부팅·촬영 검증은 남아 있다

검증한 파일 길이·모델·반복 표식·덧셈 검사는 암호 서명 검증이 아니다. 다만 전체 업데이트 경로, 장치 내부 ROM, 설치 후 부트 경로에 다른 인증이 없다고 입증한 것은 아니다. 현재 도구는 같은 크기의 바이트 교체만 처리한다. 코드·섹션 추가와 삭제, 재배치, 호출 ABI 변경은 지원하지 않는다.

실기 플래시·보조 CPU 업데이트·렌즈 EEPROM 쓰기는 하지 않았다. 원본으로의 왕복 일치, 수정 후보의 구조 검사, 실제 업데이트 수용, 부팅, 촬영·저장은 각각 별도 단계다. 마지막 세 단계는 미검증이다. 네 연구 목표의 근거·미해결 항목
