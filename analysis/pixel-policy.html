픽셀 보정 활성값의 생산과
작업 준비 함수의 호출 생략 조건

앞서 주입했던 활성 바이트를 원본 정책 함수가 만드는 경로까지 연결했다. 표 조회와 강제 설정 뒤에 다시 해제하는 조건을 확인했으며, 작업 종류 11의 준비 분기는 이 정책 호출 블록을 건너뛴다는 점도 구분했다.

픽셀 레코드·버퍼활성값 생산후속 덮어쓰기작업 준비 분기버퍼까지 연결

함수 주소는 해제 파일 오프셋이다. 컨텍스트는 같은 촬영 작업 객체를 뜻한다. 여기의 +0x49는 픽셀 레코드 보정 활성 바이트이며 보조 스케일러 활성값과 같다고 가정하지 않았다.

1. 원본 정책 함수는 세 입력으로 표를 고르고 결과 4에서 보정을 켠다

원본 0x65EA68은 +0x47/+0x48을 1, +0x49를 0으로 시작한다. 별도 플래그 +0x4A는 설정 객체와 두 메모리 마커로 정한다. 그 뒤 표 조회 결과가 4이면 +0x49/+0x4A를 모두 1로 쓴다. 정책 본문 53개 사례에서는 실행 함수를 대체하지 않았고 초기화 가드·입력 필드·설정 메모리는 준비했다. 원본 저장 명령·전체 정책 대조

단위를 부여하지 않고 확인한 세 입력과 구간

표는 파일 0x9E6242부터 104바이트씩 7개다. 원본 조회를 364개 셀과 경계값 21개에서 실행하고 반환값뿐 아니라 실제 읽은 주소도 대조했다. B의 중첩 객체는 원본 생성자 0x6EAD78로 만들었으며 기본값 0x7C를 확인했다. 전체 정책 사례에서는 B를 포함한 입력을 다시 준비했다. A·B·C를 ISO·노출 시간·온도 같은 물리량으로 명명할 근거는 아직 부족하다. 조회 주소·생성자·입력 경계

+0x3C 또는 +0x5F가 비제로이면 상수 4를 반환하는 0x5A1054를 사용한다. +0x4F가 비제로이고 설정 키 0xF5=1이며 +0x20B6≥2인 조합도 같은 강제 경로다. 세 조건을 하나씩 빼는 대조에서는 표 조회로 돌아갔다. 이 입력을 만드는 상위 함수 전체를 실행한 검증은 아니다. 강제 경로와 음성 대조

2. 최종 활성값은 정책 뒤쪽의 덮어쓰기까지 봐야 한다

디버그 조회는 디버그 객체 +4가 켜져 있을 때 해당 키 바이트를 읽는다. 키 0x1D는 픽셀 보정을 켜고 뒤의 0x1A는 끄므로 둘을 켜면 해제가 남는다. 키 0x1B/0x1C는 각각 다른 보정 플래그 +0x47/+0x48을 지운다. 표 결과와 최종 플래그를 따로 기록해 이 우선순위를 검증했다. 일곱 디버그 키·설정과 해제

마커 경로는 ID 3 조회 뒤 0x72DDAC가 반환하는 고정 RAM 0x4041F3C0의 다음 워드를 검사한다. 실험에서 ID 3 공급자를 등록하지 않았으며 이 조회의 반환 객체가 마커를 제공한다고 주장하지 않는다. 마커와 +0x9A에 의한 해제에는 디버그 객체 +4가 필요하지 않았다. 함수 마지막은 최종 +0x4A, +0x49, 선택 결과를 태그 0x3F/0x40/0x41에 각각 기록했다. 마커 조건 네 조합·최종 태그

3. 종류 11을 직접 넣은 정책 실험과 실제 준비 분기는 다르다

준비 구간에서 종류 0~11의 분기 바이트를 만든 뒤 같은 객체의 조건 분기를 실행했다. 종류 5·7·8·11에서 정책 호출 블록을 건너뛰는 결과가 나왔다. 다른 종류의 정책 입구 연결은 별도 원본 가상 호출 구간에서 검사했다. 중간 호출이 상태를 그대로 보존한다고 가정해 전체 준비 경로가 입증됐다고 표시하지 않았다. 준비 분기 12건과 실행 경계

앞선 메뉴 분석은 Pixel Shift Resolution을 내부 종류 11과 연결했다. 이번 정책을 종류 5·11로 직접 호출한 사례에서는 결과 4가 활성값을 유지했지만 그 사실만으로 실제 RAW 현상이나 Pixel Shift 준비 경로가 이 함수를 호출한다고 결론 내릴 수 없다. 종류 6에서의 해제도 내부 작업 조건이며 노출 모드 이름이나 메뉴 selector=6을 뜻하지 않는다. 실제 Pixel Shift 메뉴 연결 · 작업 종류의 원본 생산자

4. 정책 결과를 바꾸지 않고 패킷과 이미지 처리기에 넘겼다

표 결과 4를 만드는 같은 합성 입력에서 작업 종류 0과 6을 대조했다. 다른 두 보정은 원본 디버그 키 0x1B/0x1C로 해제했다. 정책의 최종 +0x49를 다시 쓰지 않고 패킷 생산 0x65D650…0x65D6B4와 처리기 0x58174C…0x581818를 이어 실행했다. 종류 0은 같은 버퍼의 중심값을 300·450으로 바꿨고 종류 6은 전체 버퍼를 유지했다. 두 연결 실행·이미지 해시

이 연결 실험에서 대체한 실행은 경과 시간 조회 0x785F70뿐이다. 보정 객체와 저장 레코드는 원본 코드로 적재했지만 촬영 입력·프레임·이벤트 봉투·디버그 상태는 준비했다. 핸들러의 기본 생성자와 RTOS 전달, 전체 촬영 준비, 실제 센서 픽셀과 JPEG 출력은 실행하지 않았다. 레코드 보정과 버퍼 수명의 앞선 검증
