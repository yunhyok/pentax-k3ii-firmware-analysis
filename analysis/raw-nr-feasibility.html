RAW 노이즈 감소를 끌 수 있는가

저장되는 RAW에 노이즈 감소가 섞여 있다면 펌웨어를 고쳐 끌 수 있을까요. 지금까지 읽어낸 것과, 아직 손대지 못한 경계를 정리했습니다.

이 문서에서

  1. 배경: RAW에 섞인 노이즈 감소란 무엇인가
  2. 공개 측정에서 첫 노이즈 감소 표시는 ISO 1600
  3. 정적 확인: LNR 레지스터 진단 경로
  4. 진단 경로와 저장 RAW 사이는 아직 끊겨 있습니다
  5. 수정 전에 넘어야 할 관문
  6. 다음 할 일과 완료 기준
  7. 한계와 남은 과제
  8. 재현 방법
  9. 근거 파일과 참고 자료

핵심 요약

  • 펌웨어 1.12를 정적으로 읽어 LNR이라는 이름의 제어 코드 구간을 찾았습니다. 노이즈 감소를 끄는 작업을 시작할 출발점입니다.
  • 저장되는 RAW의 노이즈 감소를 끌 수 있다는 근거는 아직 없습니다. 찾은 구간이 RAW 저장에 실제로 관여하는지 확인하지 못했습니다.
  • 패치는 만들지 않았습니다. 카메라에서 돌려 본 것도 없습니다. 이 문서는 결과 보고가 아니라 타당성 검토입니다.
  • 노이즈 감소가 켜졌다는 공개 측정은 ISO 1600부터 보입니다. 다만 이 수치는 외부 사이트에 올라온 RAW를 잰 것이고 분석한 펌웨어 버전의 실측이 아닙니다.

정적 분석 코드를 읽어 확인

  • 복호화한 1.12 이미지에서 LNR 레지스터 진단 함수의 주소와 문자열, 직접 호출을 읽었습니다.
  • 리터럴에서 레지스터 베이스를 올리고 특정 오프셋 값을 읽는 명령을 확인했습니다.
  • 원본·복호화 파일의 SHA-256이 기존 근거와 같습니다.

모델 외부에서 가져온 값

  • 노이즈 감소 감지 역치(ISO 1600)는 Photons to Photos에 기고된 RAW를 읽은 값입니다.
  • 분석 주소는 후보 베이스 0x02000000을 적용한 값입니다.

미확인 확인하지 못한 것

  • 찾은 진단 경로가 저장 RAW의 노이즈 감소와 이어지는지
  • 메뉴에서 Off를 골랐을 때 이 레지스터 값이 바뀌는지
  • 제어 비트 하나하나의 뜻과 Off에 해당하는 값
  • 실기에서의 레지스터 읽기·쓰기, 패치 생성·플래시·부팅

배경: RAW에 섞인 노이즈 감소란 무엇인가

RAW는 센서가 읽은 값을 거의 그대로 담은 파일입니다. 사진가가 RAW를 쓰는 까닭은 현상을 직접 하려는 데 있습니다. 노이즈 감소도 자기 손으로 조절하고 싶어 합니다.

그런데 카메라가 RAW를 저장하기 전에 노이즈를 미리 깎아 버리면 선택권이 사라집니다. 한번 뭉개진 세부는 현상 단계에서 되살릴 수 없습니다. 그래서 "메뉴에서 노이즈 감소를 꺼도 저장 RAW에 남는 처리가 있는가"가 이 조사의 질문입니다.

쉽게 말하면

RAW는 요리 전 재료입니다. 카메라가 재료를 미리 손질해서 건네면 요리사가 바꿀 수 있는 폭이 줄어듭니다. 그 손질이 메뉴를 꺼도 남는지 보려는 것입니다.

노이즈 감소가 걸렸는지는 Photons to Photos의 차트로 어느 정도 가늠합니다. 이 사이트는 사용자가 올린 RAW를 분석해, 노이즈 감소 흔적이 보이는 ISO 지점에 삼각형(▽) 표시를 붙입니다. 표시가 처음 붙는 ISO가 카메라가 손질을 시작하는 대략의 지점입니다.

공개 측정에서 첫 노이즈 감소 표시는 ISO 1600

K-3 II는 ISO 1600부터 노이즈 감소 표시가 붙습니다. ISO 100부터 1250까지는 표시가 없습니다. 다만 표시가 없다고 전처리가 전혀 없다는 뜻은 아닙니다.

K-3 III 컬러의 첫 표시는 ISO 200이라 K-3 II와 다릅니다. 두 기종을 섞지 않도록 주의해야 합니다. 차트 값은 기고된 RAW를 읽은 것이고 이번 1.12 펌웨어를 직접 측정한 결과가 아닙니다.

사용설명서도 참고했습니다. High-ISO NR(인쇄 42쪽)에는 Off가 있습니다. 장노출 NR(인쇄 39쪽)은 별도 설정입니다. 공식 FAQ는 확장 감도의 고감도 구간에서 노이즈 감소 설정과 무관하게 기본 영상 처리 시간이 늘 수 있다고 설명합니다. 공식 자료가 RAW 필터 수식이나 ISO 1600 역치를 명시하지는 않았습니다.

그래서 조사 대상은 메뉴 Off 이후에도 저장 RAW에 남는 처리입니다. K-3 III의 가속기 설명이나 노이즈 감소 함수 이름을 K-3 II의 구현 증거로 끌어오지 않습니다.

정적 확인: LNR 레지스터 진단 경로

공식 1.12 배포본을 복호화해 LNR 레지스터를 출력하는 진단 함수를 읽었습니다. 레지스터 값을 읽어 문자열로 찍는 경로입니다. 일반 촬영에서 도는 노이즈 감소 처리 자체는 아닙니다.

공식 1.12 배포본을 받아 기존 inspect_firmware.py로 해제했습니다. 해시는 기존 근거와 일치합니다. 아래 주소는 후보 코드 베이스 0x02000000을 적용한 분석 주소입니다. 실기 레지스터를 읽거나 쓴 결과가 아닙니다.

LNR이라는 약어를 특정 필터 수식으로 넓혀 읽지 않습니다. 이 블록이 JPEG 현상 전용이면 저장 RAW의 강제 노이즈 감소를 끄는 데는 소용이 없을 수 있습니다. 가장 먼저 할 일은 이 제어값을 쓰는 함수와 PEF·DNG 저장 분기가 이어지는지 확인하는 것입니다.

진단 경로와 저장 RAW 사이는 아직 끊겨 있습니다

확인한 것은 레지스터를 읽어 찍는 진단 경로 하나입니다. 메뉴 Off 값이 이 레지스터로 가는지, 이 레지스터가 저장 RAW에 작용하는지는 잇지 못했습니다.

이번 검증 결과는 nr-candidates.json에 있습니다. 전체 영상 처리 흐름은 영상 처리 안내를 참고하면 됩니다. 분석 기준 커밋은 ed0f6f0ff0fddd91f25068efbe940d035a809598입니다.

수정 전에 넘어야 할 관문

파일을 풀고 다시 포장하는 도구는 있습니다. 제어 후보도 찾았습니다. 그러나 메뉴 Off와의 연동과 설치 가능한 수정본은 아직 없습니다.

주의

기존 repack 근거의 가산 체크섬·마커 검증은 카메라 전체 인증이나 정상 부팅을 입증하지 않습니다. 조건 없이 제어 레지스터를 0으로 만들면 관련 처리·버퍼·완료 순서가 함께 깨질 수 있습니다. 비트 의미와 처리 의존성을 먼저 확인해야 합니다.

다음 할 일과 완료 기준

  1. NR-II-01 기준 RAW 확보. ISO 100·800·1250·1600·2000에서 짧은 암프레임과 평탄광을 반복 촬영합니다. High-ISO NR과 장노출 NR은 Off로 두고 Pixel Shift·HDR·다중 노출·AA 시뮬레이터는 쓰지 않습니다. 펌웨어와 촬영 조건을 정확히 기록하면 완료입니다.
  2. NR-II-02 LNR 쓰기 경로 추적. 0x20000304에 해당하는 제어값의 생산자와 설정 구조체를 찾습니다. 문자열·레지스터 이름이 같다는 것만으로 끝내지 않습니다. 메뉴값에서 이 주소까지 코드가 이어지면 완료입니다.
  3. NR-II-03 RAW와 JPEG 분리. RAW 저장 버퍼가 LNR 처리 전에 나오는지 후에 나오는지 확인합니다. 어느 쪽인지 가려지면 완료입니다. 이어지지 않으면 센서 전처리·불량 화소 보정·별도 ISP 블록으로 조사 범위를 옮깁니다.
  4. NR-II-04 최소 우회 검증. 적용 블록을 확인한 뒤 처리만 우회하고 버퍼·완료 통지는 유지합니다. On에서 기존 동작이 복원되고 Off에서 CFA 공간 통계가 바뀌면 완료입니다. 이 단계 전에는 실기 패치를 적용하지 않습니다.

필터 후보별 판별 기준과 실험 방법은 K-3 III와 묶은 검토 문서에 더 자세히 적어 두었습니다.

한계와 남은 과제

  • 이 문서는 타당성 검토입니다. 화질에 대한 결론이 아닙니다.
  • ISO 1600 역치는 외부 사이트에 기고된 RAW의 측정입니다. 분석한 1.12 펌웨어의 실측이 아닙니다.
  • 찾은 것은 레지스터를 읽어 찍는 정적 경로입니다. 실기에서 레지스터를 읽거나 쓴 적이 없습니다.
  • LNR은 펌웨어 안의 이름입니다. 뜻을 확정하지 못했습니다.
  • 이 블록이 저장 RAW에 작용하는지, 메뉴 Off와 연동되는지가 가장 큰 미확인 항목입니다.

재현 방법

원본과 복호화 파일은 이 저장소에 넣지 않았습니다. 해제는 기존 도구를 씁니다.

python inspect_firmware.py fwdc230b.bin --output-dir .private/nr-decode

도구를 중복으로 만들지 않으려고 노이즈 감소 후보 검증기는 K-3 III 저장소의 verify_nr_candidates.py에 합쳐 두었습니다. 두 저장소를 같은 상위 폴더에 두고 K-3 III 저장소에서 실행합니다.

python verify_nr_candidates.py k3ii \
  ../pentax-k3ii-firmware-analysis/.private/nr-decode/decoded.bin \
  --compare ../pentax-k3ii-firmware-analysis/analysis/nr-candidates.json
