렌즈 능력 조회에서
AF 요청 계산과 구동 준비까지

렌즈 능력 조회의 실행 조건과 16비트 구동 요청의 생산자·소비자를 연결했다. 계산한 값은 원본 CAfMotor 준비 함수의 바디·렌즈 분기까지 전달됐다. 입력 센서의 계산과 호출 사이의 스케줄링은 아직 분석 범위 밖이며, 이번 결과는 향후 AF 변경에 필요한 기본 구조를 확인한 것이다.

앞선 구동 분기능력 조회바디 요청렌즈 응답검증 범위연구 상태

코드 위치는 해제 파일 오프셋이다. ITCM 실행 주소는 VA로 구분했다. CAfMotor·CAfPulse·CAfPosition의 명칭은 펌웨어 RTTI에 근거한다. 내부 요청값을 물리 이동 거리나 초점 오차 단위로 단정하지 않았다.

1. 능력 조회는 상태 비트와 캐시값으로 결정한다

0x94DC4는 [VA 0x40006064] + 1 바이트의 비트 6을 확인한다. 비트가 꺼져 있으면 조회하지 않고 돌아간다. 켜져 있어도 CLensKaf2+6이 0이 아니면 기존 값을 사용해 0x94E78로 이어진다. 캐시가 0일 때만 명령 0x8205로 1바이트 응답을 요청한다. acquisition 조건과 사례 8건

전송 상태가 0일 때만 응답을 능력 캐시에 기록한다. 응답 비트 0은 후속 초기화 분기를, 비트 6은 앞서 확인한 바디·렌즈 구동 선택을 가른다. 이번 구동 계산 검사는 원본 조회가 캐시에 기록한 0x80과 0x40을 이어 사용했다. 능력 판정 함수를 결과 상수로 대체하지 않았다. 조회와 후속 객체 연결

2. 같은 객체의 계산값을 다음 호출이 읽는다

능력 비트 6이 꺼진 바디 분기에서는 0x544EC가 입력을 정규화한다. 방향 플래그 VA 0x00103116이 0이면 입력을 pulse+0xC2에 복사하고 차감값 VA 0x00103168을 0으로 만든다. 플래그가 0이 아니면 입력의 비트 반전 하위 16비트를 차감값으로 저장하고 pulse+0xC2를 0으로 만든다. body_calculation_input과 원본 실행

검사한 상태에서는 pulse+0xC2 − [0x00103168] + [0x0010316E]의 하위 16비트를 사용한다. 계산 플래그 accessor+0xC5F가 1이 아니거나 결과를 signed 16비트로 해석했을 때 음수이면 요청을 0으로 만든다. 전역 0x001030AB = 0, 준비 상태 3 등의 입력 조건을 고정한 검사다. 다른 상태의 전체 계산식으로 일반화하지 않았다. 계산 조건과 14개 대조 입력

전달되는 사례에서는 요청값이 pulse+0x9E와 position+0x166에 기록된다. 이어 0x52E38을 실제 호출했고, 비트 6이 꺼진 객체는 파일 0x52ED4의 바디 분기에 도달했다. 구간 번호 0·1·2의 속도나 토크 같은 물리 의미는 아직 확인하지 않았다. body_control_cases의 전달 인수·도착 주소

3. 렌즈 분기의 요청값은 0x8211 응답에서 나온다

원본 0x4E684는 전송 호출의 반환 상태를 검사하지 않고 응답 버퍼를 읽는다. 전송 상태 7을 주면서 버퍼를 갱신하지 않은 대조에서는 이전 값 0x0201이 요청 513으로 재사용됐다. 이는 지정한 전송 경계에서의 호출자 동작이다. 실제 통신 실패가 항상 버퍼를 그대로 두는지는 확인하지 않았다. lens_error_without_reply_write

반대로 정상 응답 0xFFFF는 음수로 처리돼 요청 0이 됐고 구동 준비를 호출하지 않았다. 정상 양수 0x0102는 요청 258과 잔량 필드 갱신을 거쳐 렌즈 분기에 도달했다. 이 분기는 능력 비트에 따른 제어 경로이며 SDM·DC·PLM의 물리 프로토콜을 각각 식별한 결과는 아니다. 렌즈 계산 사례 3건

4. 원본 제어 25건을 재현했고, 센서 계산은 남아 있다

python verify_af_control.py decoded.bin --emulate --compare analysis/af-control.json
python verify_af_drive.py decoded.bin --emulate --compare analysis/af-drive.json

Unicorn 2.1.4에서 능력 조회 8건, 바디 요청 계산·전달 14건, 렌즈 요청 3건을 실행했다. 55개 명령·상수, 61개 분기 목적지, RTTI 3개를 대조했고 코디네이터가 스냅샷을 다시 실행해 일치를 확인했다. 실행을 대체한 함수는 렌즈 전송 0x93F94 하나다. 나머지 객체·공유 메모리·상태값은 공개 검증기에 명시한 합성 입력이다. 검증기

위상차·콘트라스트 AF가 센서 신호에서 초점 오차를 만드는 알고리즘, 두 ITCM 호출 사이의 상태 전이, 구동 분기 이후 전체 제어와 실제 렌즈 움직임은 미검증이다. 정확한 렌즈 모델 정보가 없어도 이 기본 구조 분석은 계속할 수 있다. 모델별 패치나 렌즈 EEPROM 변경은 적용하지 않았다. 미해결 항목과 다음 작업
