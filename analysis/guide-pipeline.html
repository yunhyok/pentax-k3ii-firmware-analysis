영상 처리 경로 안내

센서가 기록한 RAW 데이터는 색 설정, 크기 조절, JPEG 압축을 거쳐 SD 카드의 파일이 됩니다. 이 주제는 K-3 II 펌웨어가 그 일을 어떤 순서로 지시하는지를 RAW 현상 함수에서 SD 카드 명령까지 따라갑니다.

핵심 요약

  • 펌웨어 코드에서 RAW 현상 작업 → 톤·화이트 밸런스·색 행렬 설정 → 색 처리 → 스케일러 → JPEG 압축 → StoreImage → Exif 작성기 → 파일시스템 → SD 명령의 연결을 이었습니다. 단계마다 “앞 단계가 남긴 주소와 길이를 뒤 단계가 읽는다”는 것을 확인하는 방식입니다.
  • 카메라 메뉴 세 가지가 이 경로에 연결됩니다. Custom Image의 Reversal Film은 톤 선택값 6이 되고, Pixel Shift Resolution은 전용 작업 종류를 고르며, RAW 현상의 Color Fringe Correction은 색 처리를 한 번 더 돌립니다.
  • 확인은 모두 PC에서 했습니다. 펌웨어의 ARM 기계어를 CPU 에뮬레이터에서 구간별로 실행하고, 버퍼 주소나 장치 응답 같은 입력은 직접 만들어 넣었습니다.
  • 영상 처리 회로가 픽셀을 처리하는 모습, JPEG가 실제로 만들어지는 모습, SD 카드에 기록되는 모습은 한 번도 관측하지 않았습니다. 확인한 것은 소프트웨어가 값을 계산해 넘기는 데까지입니다.

배경 지식

세부 문서를 읽기 전에 알아 두면 좋은 개념입니다.

RAW 현상과 Custom Image

RAW는 센서가 읽은 값을 거의 그대로 담은 데이터입니다. 카메라는 여기에 밝기 곡선(톤), 화이트 밸런스, 색 변환을 적용해 JPEG를 만듭니다. 이 과정을 현상이라고 합니다. K-3 II에서 사진의 마무리 느낌을 고르는 메뉴가 Custom Image이며, Bright부터 Cross Processing까지 11가지가 있습니다(사용설명서 56쪽, 사양). 펌웨어 안에서 RAW 현상을 맡는 함수는 진단 문자열에 DevelopmentRawImage라는 이름으로 나옵니다.

작업, 레시피, 모듈

펌웨어는 사진 한 장의 처리를 작업 객체 하나로 다룹니다. 작업에는 “어느 모듈을 어떤 순서로 부를지” 적은 명령 배열이 붙는데, 이 연구에서는 레시피라고 부릅니다. 모듈은 번호가 붙은 처리 단위이고, 컨트롤러가 레시피를 한 줄씩 읽어 해당 모듈에 메시지를 보냅니다. 모듈이 끝나면 완료 메시지가 돌아오고 다음 줄로 넘어갑니다.

디스크립터와 “주소가 같다”의 뜻

모듈끼리는 영상을 복사해 넘기지 않습니다. 영상 버퍼의 주소와 크기를 적은 작은 구조체(디스크립터)를 넘깁니다. 그래서 이 주제의 문서들은 “앞 모듈이 적은 주소 칸을 뒤 모듈이 읽는가”를 따집니다. 주소가 이어진다는 것은 확인했지만, 그 주소의 메모리에 실제로 올바른 픽셀이 들어 있었는지는 확인한 적이 없습니다.

JPEG와 Exif 파일

카메라의 JPEG 파일은 시작 표식(SOI) 뒤에 촬영 정보를 담은 Exif 구획(APP1)이 오고, 그 뒤에 압축된 영상 데이터가 이어집니다(미국 의회도서관의 형식 설명). K-3 II는 Exif 2.30을 따르는 JPEG를 만듭니다. 펌웨어는 헤더와 압축 데이터를 따로 준비해 두 번에 나눠 씁니다.

SD 카드에 쓰는 방법

SD 카드는 512바이트 블록 단위로만 씁니다. 한 블록은 CMD24, 연속한 여러 블록은 CMD25 명령으로 씁니다. 데이터는 CPU가 한 바이트씩 보내지 않고 컨트롤러 회로가 메모리에서 직접 가져가는데(DMA), 가져갈 위치를 적은 표가 ADMA2 설명자 표입니다. 규격은 SD Association의 간이 규격에 있고, 이 연구는 같은 규격을 구현한 Linux의 정의와 대조했습니다. K-3 II에는 SD 슬롯이 두 개 있고, 펌웨어에도 SD 포트 두 개의 설정이 있습니다.

“원본 코드 실행으로 확인”의 뜻

이 주제의 검증은 펌웨어에 든 ARM 기계어를 PC의 CPU 에뮬레이터(Unicorn)에서 실행하는 방식입니다. 계산과 분기는 원본 코드가 하지만, 메모리의 내용과 장치의 응답은 연구자가 만들어 넣었습니다. 대부분은 함수나 구간을 따로 실행한 것이고, 처음부터 끝까지 이어서 돌린 것이 아닙니다. 네 가지 검증 표시의 정의는 개요의 검증 수준 읽는 법에 있습니다.

문서에 나오는 내부 이름

이 주제의 문서에는 낯선 이름이 여럿 나옵니다. 제조사가 공개한 이름이 아닙니다. 펌웨어에 남은 진단 문자열에서 가져왔거나, 코드의 역할을 보고 연구자가 붙인 이름입니다.

“확인”과 “모델”이 함께 붙은 항목은 원본 코드를 실행했지만 입력이나 장치 응답은 연구자가 넣었다는 뜻입니다.

읽는 순서

조사한 날짜순이 아니라 데이터가 흘러가는 순서로 읽으면 이해하기 쉽습니다. 앞의 세 문서가 줄기이고, 뒤의 세 문서는 조건에 따라 갈라지는 가지를 다룹니다.

  • 먼저 읽기

    하드웨어 식별과 RAW 현상 개관

    RAW 현상 함수는 어디에 있고, 톤 곡선은 어떻게 계산되는가.

    현상 함수와 호출 지점을 찾았고, 곡선 계산을 원본 코드 실행으로 맞췄습니다. 시작하기 주제의 문서입니다.

  • 1단계

    RAW 이후의 톤·WB·색 행렬

    RAW 작업은 어떻게 톤 설정에 닿는가. 톤 선택값 6은 무엇이고, 색 설정값은 어떻게 레지스터에 들어가는가.

    작업 목록과 레시피를 이었고, 선택값 6이 Reversal Film임을 확인했습니다.

  • 톤 계산 상세

    톤 문맥과 곡선 생산자의 연결

    곡선의 입력값은 어디서 오며, 어느 작업 객체를 공유하는가.

    원본 코드 24개 사례에서 문맥 계산, 곡선 생성, 조건부 복사를 나누어 재현했습니다. 실제 촬영의 실행 순서는 아직 확인하지 못했습니다.

  • 2단계

    JPEG 출력 버퍼와 Reversal Film 메뉴

    처리된 영상은 어떤 버퍼를 거쳐 JPEG가 되고 파일 조각이 되는가. 메뉴는 어떻게 선택값을 기록하는가.

    네 모듈이 같은 주소와 길이를 넘기고, Exif 작성기가 두 조각으로 씁니다.

  • 3단계

    파일시스템에서 SD·DMA까지

    파일 쓰기 요청은 어떻게 SD 명령과 DMA 설정이 되는가.

    백엔드 A를 CMD24·CMD25와 ADMA2 설명자 표까지 이었습니다.

  • 4단계

    백엔드 B와 두 번째 CPP 출력

    용량이 큰 카드에서 고르는 백엔드 B도 같은 SD 경로로 가는가. 색 처리의 두 번째 출력은 어디로 가는가.

    B도 같은 카드 객체에 닿고, 두 번째 출력은 모듈 17의 입력이 됩니다.

  • 5단계

    마스크 CPP와 보조 JPEG 입력

    마스크 분기의 보조 출력은 JPEG로 이어지는가. Color Fringe Correction은 무엇을 바꾸는가.

    보조 JPEG 입력은 찾았지만 보조 스케일러를 켜는 조건은 남았습니다.

  • 6단계

    Pixel Shift 메뉴와 버퍼 수명

    Pixel Shift 메뉴는 어떤 작업을 고르는가. 버퍼는 언제 만들어지고 풀리는가.

    메뉴가 작업 종류 11로 이어지고, 일반 버퍼와 마스크 버퍼의 수명이 다릅니다.

함께 읽으면 좋은 문서도 있습니다. JPEG 완료 길이가 저장 레코드에 들어가는 과정은 JPEG 완료값과 저장 레코드가, 톤 보간 함수를 C로 다시 만든 시험은 톤 보간 함수 C 재구현이 다룹니다.
