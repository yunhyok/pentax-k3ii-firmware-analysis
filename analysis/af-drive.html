렌즈 응답의 비트 6이
AF 구동 준비 경로를 가른다

렌즈 명령 0x8205의 응답이 저장되는 곳과, 그 값을 읽어 렌즈 명령 또는 바디 드라이버로 분기하는 원본 코드를 연결했다. 합성 응답 6개에서 두 경로와 오류 시 값 보존을 확인했다. 실물 렌즈의 구동·AF 성능이나 특정 렌즈용 수정 펌웨어를 검증한 결과는 아니다.

초기 분석능력값 생산자구동 분기렌즈별 조건검증·한계재포장연구 상태

코드 위치는 해제 이미지의 파일 오프셋이다. 일부 명령은 시작 시 SRAM으로 복사되므로 단순히 0x02000000을 더한 주소에서 실행하면 안 된다. 원본 복사 표 4개를 재현해 해당 실행 주소를 사용했다. 복사 표·클래스 RTTI·분기 근거

후속 AF 제어 분석에서 능력 조회 조건과 요청값 계산·소비를 25개 원본 ARM 사례로 검증했다. 입력 센서 알고리즘과 물리 구동의 한계는 남아 있다.

1. 성공한 응답만 능력 바이트를 갱신한다

CLensSdm 경로 0x94DC4는 CLensKaf2+6이 0이면 명령 0x8205를 준비한다. 디스패처 0x94204와 처리기 0x94844는 한 바이트를 요청하고 전송 결과가 0일 때만 0xB9B5C로 응답을 저장한다. CAfLens의 0x4C500은 그 바이트의 0x40 비트를 추출한다. 원본 생산자·저장·조회 검증

2. 두 분기는 서로 다른 구동 요청을 만든다

원본 CAfMotor 진입점 0x52E38에 준비된 객체와 인수 5를 넣었다. 비트 6이 켜지면 0x4DD6C를 거쳐 렌즈 명령 0x8920, 0x8900을 제출했다. 시험 위치값 0x0345는 두 바이트 03 45로 준비됐다. 비트가 꺼지면 렌즈 명령을 보내지 않고 0x52D18 → 0x5234C → 0x47D80에 도달했다. 6개 연쇄 실행과 출력 인수

응답 / 전송 결과이전 값 → 저장값원본 분기
00 / 000 → 00바디 드라이버
40 / 000 → 40렌즈 명령
C0 / 000 → C0렌즈 명령
80 / 000 → 80바디 드라이버
40 / 700 → 00바디 드라이버. 오류 응답 미반영
00 / 740 → 40렌즈 명령. 이전 능력값 유지

바디 하위 연결 0x47CD0 → 0x332E8 → 0x33250 → 0xB90B0도 직접 분기로 확인했다. 이 구간의 물리 모터 출력은 실행하지 않았다. 반대편도 렌즈 전송 보조 함수를 대체했으므로 실제 렌즈가 명령을 수락하거나 이동했다는 증거는 아니다.

현재 AF 연구의 목적은 향후 변경을 위한 기본 구조 확보다. 렌즈별 패치나 실제 구동 적용은 이번 범위가 아니다. 실물 렌즈 식별 정보가 없어도 정보 판독·정책·AF 계산·구동 명령의 정적 분석은 계속한다.

3. 서비스의 SDM On과 실제 AF 분기를 구분했다

서비스 문자열 SDM On은 0x85B088 → 0x5CA85C → 0x5D7034를 거쳐 명령 0x8601에 값 2를 전달한다. 이번에 확인한 AF 명령 0x8205/0x8900과는 다른 경로다. 서비스 메뉴 이름만으로 촬영 AF의 구동 선택을 설명하지 않았다. 서비스·AF 명령의 분리 근거

렌즈별 분기 가능성도 조사했다. 0x4B9F8은 전송 객체의 인덱스 0x13, 즉 +0xF7의 바이트를 읽는다. 원본 분기 0x4D3F8은 값 F1과 F2를 각각 0x4D1BC와 0x4D2BC로 보낸다. 이는 내부 모델 구분 경로의 증거지만 사용자의 실물 렌즈가 그 값을 보고한다는 증거는 아니다.

Ricoh는 K-3 II에서 렌즈 내 AF 모터를 갖춘 렌즈를 장착하면 해당 모터로 자동 초점을 맞춘다고 설명한다. 구형 smc DA★ 16–50mm F2.8 ED AL [IF] SDM과 smc DA★ 50–135mm F2.8 ED [IF] SDM은 SDM 비지원 바디에서 바디 모터를 사용할 수 있다는 공식 설명이 있다. 같은 초점거리의 후속 PLM 렌즈나 모든 SDM·DC 렌즈에 이 특성을 일반화하지 않는다. K-3 II 공식 FAQ · 구형 16–50 SDM · 구형 50–135 SDM

따라서 공통 능력 비트를 무조건 지우는 수정은 특정 렌즈용 해결책으로 채택하지 않았다. 정확한 대상 모델, 실물 식별 응답, 두 구동 방식의 기계적 지원, 나머지 AF 상태 전이와 오류 복구를 확인해야 변경 범위를 정할 수 있다.

4. 원본 실행과 미실행 경계

조정 에이전트가 독립 작업자의 스크립트·후크를 검토하고 결과 스냅샷을 다시 실행해 일치시켰다. 고정 명령 33개, 직접 분기 36개, 해시 구간 11개, 시작 복사 행 4개를 확인했다. 합성 실행은 구동 사례 6개와 내부 모델 분기 3개다. 재현 코드 · 결과

python verify_af_drive.py decoded.bin --emulate --compare analysis/af-drive.json

렌즈 전송 0x93F94/0x93D24, 바디 준비 0x47E38/0x47E58, 위치 기록 0x41E08은 대체했다. AF 센서 재설정에 관한 합성 상태도 고정했다. 센서의 초점 판단, 전체 AF 상태 기계, 모터 이동과 정지, 렌즈별 시간 제약은 검증하지 않았다. 비트 6으로 선택되는 경로 안에서 SDM·DC·PLM을 구분하는 물리 프로토콜도 미확정이다.

패치 후보 적용, 카메라 플래시, 렌즈 EEPROM 변경은 하지 않았다. 현재 결과는 렌즈 응답과 원본 구동 요청의 연결이며 동작 가능한 SDM→스크루 전환 펌웨어는 아니다.
