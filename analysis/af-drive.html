AF와 렌즈 제어 · 1단계 구동 방식 선택

렌즈 응답의 비트 하나가 AF 구동 경로를 가릅니다

K 마운트 AF 렌즈에는 카메라 바디의 모터로 초점을 돌리는 것과 렌즈 안의 모터로 도는 것이 있습니다. 카메라가 둘 중 어느 쪽으로 구동할지 정하는 코드를 찾아 원본 기계어로 따라가 보았습니다.

핵심 요약

  • 카메라는 렌즈에 명령을 보내 1바이트짜리 응답을 받고 이를 “능력 바이트”로 저장합니다. 이 바이트의 비트 6이 1이면 렌즈 명령 경로, 0이면 바디 드라이버 경로로 AF 구동 준비가 진행됩니다.
  • 응답은 전송이 성공했을 때만 저장됩니다. 전송이 실패하면 이전에 저장된 값이 그대로 남습니다.
  • 연구자가 만든 응답 6가지를 넣어 두 경로를 모두 실행했습니다. 렌즈 경로에서는 렌즈 명령 두 개가 준비됐고, 바디 경로에서는 바디 드라이버 함수의 입구에 도달했습니다.
  • 실물 렌즈를 붙이거나 모터를 움직인 결과가 아닙니다. 특정 렌즈의 구동 방식을 바꾸는 수정 펌웨어를 만든 것도 아닙니다.

확인 원본 코드 실행으로 확인

  • 응답 바이트의 저장 조건과 비트 6 추출
  • 두 구동 경로의 분기(6건)
  • 렌즈 경로가 준비한 명령 번호와 바이트
  • 렌즈 모델 바이트에 따른 내부 분기(3건)

정적 분석 코드를 읽어 판단

  • 바디 드라이버 입구 아래의 호출 연결
  • 서비스 메뉴 “SDM On”이 보내는 명령
  • 함수들이 서로를 부르는 관계(분기 36개)

모델 시험 조건으로 정한 것

  • 렌즈의 응답 바이트와 전송 결과
  • 미리 준비해 넣은 객체와 인수
  • 렌즈 전송, 바디 준비, 위치 기록 함수 5개는 대체

미확인 확인하지 않은 것

  • 실물 렌즈가 어떤 값을 응답하는지
  • 모터의 이동과 정지, AF 성능
  • SDM·DC·PLM을 구분하는 통신 규약
  • AF 전체의 상태 전이와 오류 복구

배경: K 마운트의 두 가지 AF 구동 방식

K 마운트 렌즈의 자동 초점은 두 방식으로 구동됩니다. 리코의 마운트별 호환표는 이를 “AF 커플러(바디 구동)”와 “SDM·DC·PLM(렌즈 구동)”으로 나눕니다.

  • 바디 구동 — 바디 안의 모터가 마운트에 있는 회전축(AF 커플러)을 돌려 렌즈의 초점 기구를 움직입니다.
  • 렌즈 구동 — 렌즈 안에 든 모터가 초점 기구를 움직입니다. 바디는 전기 접점으로 명령만 보냅니다. SDM, DC, PLM은 렌즈 안 모터의 종류를 가리키는 PENTAX의 이름입니다.

K-3 II의 마운트는 KAF2입니다. 제품 사양에 따르면 AF 커플러, 렌즈 정보 접점, 전원 접점을 모두 갖추고 있어 두 방식을 다 쓸 수 있습니다. 리코의 K-3 II FAQ는 모터를 내장한 렌즈를 붙이면 카메라가 렌즈 안 모터로 구동하는 자동 초점으로 자동 전환한다고 설명합니다. 이 문서는 그 전환을 정하는 코드를 다룹니다.

펌웨어에는 C++ 클래스 이름이 남아 있어 코드의 역할을 짐작하는 데 도움이 됩니다. 이 문서에 나오는 CAfMotor, CAfLens, CLensKaf2, CLensSdm은 펌웨어 안의 RTTI 문자열에서 확인한 이름입니다. 이름이 마운트 종류(KAF2)와 모터 방식(SDM)을 가리키지만, 각 클래스가 실제로 하는 일은 아래에서 실행으로 확인한 범위까지만 말할 수 있습니다.

주소 표기

코드 위치는 복호화한 이미지의 파일 오프셋입니다. 일부 코드는 시작할 때 RAM으로 복사되어 다른 주소에서 실행되므로, 오프셋에 0x02000000을 더한 주소에서 그대로 실행하면 안 됩니다. 검증기는 펌웨어에 들어 있는 복사 표 4행을 그대로 재현해 실행 주소를 맞췄습니다.

능력 바이트: 성공한 응답만 저장됩니다

렌즈 명령 0x8205의 1바이트 응답은 전송 결과가 0(성공)일 때만 저장되고, AF 코드는 그 바이트의 비트 6만 꺼내 씁니다.

능력을 묻는 쪽은 CLensSdm의 함수 0x94DC4입니다. 저장된 능력 바이트(CLensKaf2 객체의 6번 바이트)가 0이면 명령 0x8205를 준비합니다. 명령 디스패처와 처리기는 1바이트를 요청하고, 전송 결과가 0일 때만 응답을 저장합니다. CAfLens의 함수 0x4C500은 저장된 바이트에서 비트 6(값 0x40)만 꺼내 0 또는 1로 돌려줍니다. 비트 7만 켜진 응답은 0으로 판정됩니다.

조회가 어떤 조건에서 실행되는지는 다음 문서에서 더 자세히 다룹니다. 렌즈를 붙였을 때 진행되는 전체 순서는 실행하지 않았습니다.

구동 준비: 같은 시작점에서 두 경로로 갈립니다

AF 구동 준비 함수는 비트 6이 1이면 렌즈에 보낼 명령을 준비하고, 0이면 렌즈 명령 없이 바디 드라이버로 갑니다.

시험에서는 원본 CAfMotor의 구동 준비 함수 0x52E38에 준비한 객체와 인수 5를 넣었습니다. 분기 직전에 비트를 억지로 바꾸지 않았고, 앞 절의 원본 저장·조회 코드가 만든 값을 그대로 썼습니다.

  • 렌즈 명령 경로 — 렌즈 명령 0x8920(1바이트)과 0x8900(2바이트)이 차례로 전송 함수에 넘어갔습니다. 시험용으로 넣어 둔 위치값 0x0345는 두 바이트 03 45로 준비됐습니다.
  • 바디 드라이버 경로 — 렌즈 명령은 하나도 나가지 않았습니다. 바디 드라이버 입구 0x47D80에 목표값 0x12가 전달되는 것까지 확인하고 멈췄습니다.

주의

두 경로 모두 끝까지 간 것이 아닙니다. 렌즈 쪽은 전송 함수를 대체했으므로 실제 렌즈가 명령을 받아들이거나 움직였다는 증거가 아닙니다. 바디 쪽은 드라이버 입구에서 멈췄고, 그 아래의 물리 모터 출력은 실행하지 않았습니다.

  • 바디 경로에서 드라이버 입구에 도착했을 때의 인수는 r1 = 0, r2 = 0x12였습니다. 0x12는 시험 전에 VA 0x0010314A에 넣어 둔 값입니다.

  • AF 센서 재설정과 관련된 분기를 타지 않도록 상태값 세 개(VA 0x001030A4, 0x001030AB, 0x001030AF)를 고정했습니다.
  • 구동 준비가 끝난 뒤에도 능력 바이트는 저장된 값 그대로였습니다.

서비스 메뉴의 “SDM On”과 렌즈 모델 분기는 별개입니다

펌웨어에는 SDM과 관련된 경로가 더 있지만, 위에서 본 촬영 AF의 구동 선택과는 다른 명령·다른 값을 씁니다.

이름이 비슷하지만 서로 다른 세 경로
경로쓰는 값확인한 내용상태
촬영 AF의 구동 선택능력 조회 0x8205, 구동 0x8920·0x8900이 문서의 앞 두 절확인
서비스 문자열 “SDM On”명령 0x8601에 값 20x85B088 → 0x5CA85C → 0x5D7034로 이어지는 호출과 상수정적 분석
렌즈 모델 바이트값 F1, F2값에 따라 서로 다른 내부 분기로 감(3건 실행)확인

서비스 메뉴의 이름만 보고 촬영 AF의 구동 선택을 설명하면 안 됩니다. “SDM On”은 AF 명령과 다른 번호의 명령을 보냅니다.

렌즈마다 다르게 동작할 가능성도 조사했습니다. 함수 0x4B9F8은 전송 객체에서 인덱스 0x13의 바이트(객체의 +0xF7)를 읽습니다. 원본 분기 0x4D3F8은 이 값이 F1이면 0x4D1BC로, F2이면 0x4D2BC로, 그 밖의 값(시험에서는 0)이면 0x4D054로 갑니다. 펌웨어가 특정 렌즈 모델값을 따로 다룬다는 증거입니다. 그러나 사용자의 실물 렌즈가 그 값을 보고한다는 증거는 아닙니다.

참고

ExifTool의 PENTAX 렌즈 표에서 모델 번호 241(0xF1)은 smc PENTAX-DA★ 50-135mm F2.8 ED [IF] SDM, 242(0xF2)는 smc PENTAX-DA★ 16-50mm F2.8 ED AL [IF] SDM입니다. 숫자는 위의 분기값과 같습니다. 하지만 펌웨어가 읽는 바이트가 사진 파일에 기록되는 렌즈 모델 번호와 같은 것인지는 이 연구에서 확인하지 않았습니다.

공식 자료가 말하는 것

구형 smc PENTAX-DA★ 16-50mm F2.8 ED AL [IF] SDM과 smc PENTAX-DA★ 50-135mm F2.8 ED [IF] SDM의 제품 설명에는 SDM을 지원하지 않는 바디에서는 바디의 모터로 AF를 할 수 있다고 적혀 있습니다. 두 렌즈가 두 구동 방식을 모두 갖췄다는 뜻입니다. 같은 초점거리의 후속 PLM 렌즈나 다른 모든 SDM·DC 렌즈가 그렇다고 일반화할 수는 없습니다.

이런 이유로 “능력 비트를 무조건 지워서 바디 구동으로 돌린다” 같은 수정은 특정 렌즈의 해결책으로 채택하지 않았습니다. 변경 범위를 정하려면 정확한 대상 모델, 실물 렌즈의 식별 응답, 두 구동 방식의 기계적 지원 여부, 나머지 AF 상태 전이와 오류 복구를 먼저 확인해야 합니다.

서비스 경로와 모델 분기의 주소
  • 서비스 문자열 SDM On은 파일 0x85B26C에 있습니다. 호출은 0x85B088 → 0x5CA85C, 0x5CA868 → 0x5D7034, 0x5D7078 → 0x5D6E4C이고, 명령 번호 0x8601은 0x5D7070의 명령에 들어 있습니다.
  • 모델 바이트: 0x4D404 → 0x4B9F8(값 읽기), 0x4BA00 → 0x9025C. 비교 명령은 0x4D468(F1)과 0x4D498(F2)이고, 분기는 0x4D4F0 → 0x4D1BC, 0x4D4E4 → 0x4D2BC입니다.
  • 근거는 af-drive.json의 model_and_service와 native_profile_cases입니다.

한계와 남은 과제

이 결과는 렌즈 응답과 원본 구동 요청 사이의 연결을 확인한 것입니다. 구동 방식을 SDM에서 바디 구동으로 바꿔 주는, 동작하는 펌웨어가 아닙니다.

  • 실행하지 않은 범위 — AF 센서의 초점 판단, AF 전체의 상태 전이, 모터의 이동과 정지, 렌즈별 시간 제약.
  • 구분하지 못한 것 — 비트 6으로 선택되는 렌즈 명령 경로 안에서 SDM·DC·PLM을 구분하는 통신 규약.
  • 하지 않은 일 — 수정 후보 적용, 카메라 플래시 기록, 렌즈 EEPROM 변경.

AF 연구의 현재 목적은 나중에 변경을 검토할 때 필요한 기본 구조를 확보하는 것입니다. 실물 렌즈의 식별 정보가 없어도 정보 읽기, 판단, AF 계산, 구동 명령의 분석은 이어 갈 수 있습니다. 능력 조회의 조건과 요청값 계산은 AF 요청 계산과 구동 준비에서 다룹니다.

재현 방법

입력은 복호화 도구가 만든 decoded.bin이고, 에뮬레이터는 Unicorn 2.1.4입니다.

python verify_af_drive.py decoded.bin --emulate --compare analysis/af-drive.json
