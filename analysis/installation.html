업데이트 검사 다음의 전송과
기록 오류 전달을 추적했다

보조 CPU 경로는 64바이트씩 960회 전송하고 전체 60 KiB를 다시 읽어 비교한다. 주 이미지 경로는 RAM에 복사한 송신기와 공통 수신기를 거친다. 프로그램 함수의 오류값이 응답 슬롯에 기록되지 않는 지점을 확인했으며, 상위 함수의 후속 비교가 불일치를 반환하는 조건도 별도로 재현했다.

앞선 재포장 분석보조 이미지주 이미지오류 전달재현·한계연구 상태

코드 위치는 해제 파일 오프셋이다. VA 표기는 실행·데이터 주소다. 원본 ARM 명령은 Unicorn의 합성 메모리에서 실행했다. 전송·GPIO·NOR 상태를 제공한 경계는 각 결과에 명시했다. 실물 장치에 기록한 결과는 아니다.

1. 보조 이미지: 전송 오류와 내용 불일치는 다르게 처리한다

두 이미지의 길이·표식·체크섬 검사 이후 호출 0x5D663C → 0x5D633C은 0x5D5370으로 이어진다. 이 함수가 전달하는 영역은 이미지 시작점에 0x1000000을 더한 보조 이미지다. 주 이미지 기록 전체를 이 함수와 같은 경로로 해석하면 안 된다. 분기·상수·실행 결과 · 검증 코드

2. 주 이미지: RAM 송신기와 메모리 매핑 기록 명령

0x73CFF4를 실행하면 파일 0xB324부터 0x62C바이트가 VA 0x40304000으로 복사된다. 복사 결과를 원본과 바이트 단위로 대조한 뒤 실제 래퍼 0x630114/0x63011C/0x63015C에서 RAM 송신기로 들어갔다. 비교·지우기·프로그램 요청은 앞서 합계 명령 7에서 확인한 VA 0xC0001FD0 계열 슬롯을 사용한다. RAM 복사와 원본 송수신 실행

지우기 함수는 VA 0x02000AAA / 0x02000554에 AA·55·80·AA·55를 기록한 뒤 대상 주소에 30을 쓴다. 프로그램 함수는 대상에 25·7F, 128개의 16비트 값, 29를 순서대로 쓴다. 합성 RAM에서 명령 주소·데이터·횟수를 모두 대조했다. 이 패턴만으로 제조사나 정확한 플래시 부품 번호를 확정하지 않았다. 메모리 쓰기 순서 검증

3. 프로그램 오류 2가 응답 슬롯에 남지 않는다

상태 검사 함수 0xD9CD0에 실패값 0을 제공하면 원본 프로그램 함수 0xD9EB4는 첫 블록 후 중단하고 2를 반환한다. 그러나 수신기의 0xDA2A8 호출 다음 명령은 R0 = 0xA다. 비교·지우기 분기와 달리 반환값을 결과 슬롯에 저장하지 않는다. 원본 수신기가 앞서 결과 슬롯을 지운 상태이므로 송신기는 완료값 0xA와 결과 0을 받는다. 이 차이는 성공·실패 사례에서 모두 확인했다. program_poll_success / program_poll_failure

일반 섹터 쓰기 함수 0x599914와 실제 업데이트의 블록 함수 0xBFD0 모두 프로그램 응답이 0이면 다시 내용을 비교한다. 래퍼 반환값을 공급한 별도 원본 제어 검사에서 기록 응답 0 뒤 비교 결과 3을 주면 최종 반환도 3이었다. 두 함수를 같은 진입점으로 취급하지 않았다. 프로그램 오류와 실제 플래시 내용 불일치가 실물에서 어떻게 나타나는지까지 검증한 결과는 아니다. primary_control과 actual_updater의 블록 사례

실제 갱신에서는 첫 섹터를 마지막에 처리한다

앞선 보조 함수 0x5D633C는 0 또는 1을 반환하고, 0x5D6664는 0일 때 갱신 진입을 건너뛴다. 반환값 1인 정상 경로에서는 0x630174 → RAM의 0xC278로 인수 (2, 0)을 전달했다. 앞서 0x73CF94가 파일 0xB950…0xEF6E를 VA 0x4030462C로 복사한다. 따라서 실제 업데이트의 0xC07C → 0xBFD0도 RAM 코드다. 원본 복사와 진입 분기 대조

일반 진입의 두 번째 인수 0에서는 128 KiB 섹터 1…127 중 13…22를 건너뛰고, 나머지가 성공한 뒤 섹터 0을 마지막으로 처리한다. 블록 함수는 ((대상 VA − 0x02000000) & ~1)에 이미지 포인터를 더해 원본 버퍼를 고른다. 섹터 루프의 오류는 즉시 반환되고, 상위 0xC278는 전체 패스를 최대 16회 시도한다. 반복 검사에서는 마지막 MMIO·전원 제어 루프 진입 전에 멈췄다. 섹터 순서 6건과 패스 재시도 3건

두 번째 인수가 1인 별도 분기는 기본 순회 후 섹터 13과 22를 추가 처리한다. 이때 첫 추가 호출의 반환값은 검사하지 않고 두 번째 호출 결과로 덮는다. 섹터 13에만 오류를 공급한 사례에서도 섹터 22와 0까지 진행해 최종 0을 반환했다. 일반 업데이트의 인수 0과 구분해야 하며, 이 별도 분기의 사용자 도달 조건은 아직 검증하지 않았다. variant1_first_special_sector_status_overwritten

Unicorn 2.1.4에서 보조 제어 7건, 직렬 전달 4건, 주 이미지 송수신 9건, 일반 쓰기 제어 7건을 확인했다. 실제 갱신 루틴은 진입 2건, 블록 제어 5건, 섹터 순서 6건, 패스 재시도 3건을 추가했다. 해제본 SHA-256은 1b87bf35b290e4b4e8910beb4055c34f97504b65e249ad65e5ccc0402bd14cfc로 고정한다. 공개 CI에는 펌웨어가 없으므로 문서·파일 경계와 단위 검사만 실행한다. 원본 명령 검증은 로컬 재현 결과다.

보조 CPU의 원격 수신기와 실제 플래시 목적지, 보존 영역의 의미, 전원 중단 복구, 설치 후 부트 경로는 아직 검증하지 않았다. 각 단계의 반환값을 공급한 검사와 실제 연결 실행을 구분했으며 전체 설치를 실행한 결과는 아니다. NOR 상태 함수를 대체했으므로 물리 기록 성공도 주장하지 않는다. 이번 결과는 재포장·검사 다음의 제어 경로를 좁힌 것으로, 카메라 업데이트·부팅·촬영 수용은 별도 과제다.
