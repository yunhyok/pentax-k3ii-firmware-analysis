백엔드 B는 같은 SD 카드 객체로,
두 번째 CPP 출력은 합성 입력으로

백엔드 B의 파일 쓰기를 CMD24·CMD25와 ADMA 설명자 생성까지 연결했다. 두 번째 CPP 출력은 모듈 17의 별도 입력이며, 기본 주소 분기에서는 합성 목적지가 일반 스케일러의 입력과 같다. 마스크 분기는 목적지가 달라 JPEG까지 이어지는 경로를 확정하지 않았다.

초기 분석앞선 SD·버퍼 분석백엔드 B섹터 버퍼CPP 합성마스크 분기검증·재현남은 범위

후속 검증: 보조 스케일러 두 출력과 JPEG 보조 입력의 조건부 주소 공유, RAW 현상 메뉴와 모드 생산자를 추가했다. 아래는 앞선 조사 범위이며 마스크 분기의 최신 결론은 후속 보고서를 참고한다.

코드 주소는 해제 이미지의 파일 오프셋이며 코드 VA는 오프셋 + 0x02000000이다. 장치 MMIO와 합성 메모리 주소는 절대 주소로 표시했다. 원본 ARM 명령을 합성 상태에서 실행한 결과이며, 카메라 촬영이나 물리 SD 기록 결과가 아니다.

1. 백엔드 B의 파일 쓰기와 SD 명령을 연결했다

이전 보고서는 B의 진입점 0x5CB860 → 0x5CB814 → 0xE86818까지 확인했다. 이번에는 디스패처가 파일 핸들에서 드라이브를 찾고, 파일시스템 함수표의 쓰기 슬롯을 호출하는 과정을 추적했다. 함수표 VA 0x02F1394C는 행 크기 0x84, 쓰기 슬롯 +0x20을 사용한다. 첫 행은 0xEAFFAC → 0xEB1A94로 이어진다. 실행 사례는 이 첫 행과 이미 할당된 파일 영역을 준비했다. 다른 구현·전체 마운트·클러스터 할당까지 확인한 것은 아니다. 함수표·호출·실행 근거

클러스터 주소 계산 0xEBD250은 (cluster−2) × drive[+0x34] + drive[+0x30] + uint64(drive[+0x18], drive[+0x1C])를 사용한다. 합성 상태에서는 cluster=2, 클러스터당 8섹터, 시작값 0x100, 데이터 오프셋 0x20으로 LBA 0x120이 나왔다. 이후 바이트 위치를 섹터 크기 512로 나눈다. 값과 단위는 이번 입력 조건이며 모든 볼륨의 구성값으로 일반화하지 않는다. 검증 코드의 드라이브 상태와 기대값

2. 앞·가운데·끝에서 전달하는 포인터가 다르다

파일 위치 7에서 1,030바이트를 쓰면 첫 섹터에 505바이트, 가운데 섹터에 512바이트, 마지막 섹터에 13바이트가 배치된다. 앞뒤 부분은 기존 섹터를 읽어 캐시에 복사하고, 가운데는 소스 주소에 505를 더한 포인터를 그대로 전달한다. 카드 진입점의 객체·LBA·개수·소스·내용과 ADMA 표 전체 2,048바이트를 대조했다. offset 7·1,030바이트 실행 사례

3. 두 번째 CPP 출력의 소비자는 모듈 17이다

job+0x59 != 0으로 두 번째 반복이 생기고 CPP의 payload+0x84 != 0이면 job+0x2194의 평면들이 CPP 출력으로 선택된다. 모듈 17 설정 0x65D564…0x65D628은 같은 디스크립터를 payload+0x1C에 넣는다. 기본 분기에서는 payload+0x18과 +0x20 모두 job+0x2140을 가리킨다. 즉 첫 번째 이미지와 목적지가 같은 디스크립터를 공유한다. 설정 생산자·수신자·요청 조립 근거

수신 경로는 0x589904 → 0x589888 → 0x58980C → 0x5AB310이며, 수신 함수의 허용 조건을 별도로 재실행했다. 내부 0x5AF684…0x5AF798은 두 색차 평면에 대한 요청을 만들고, 내부 모드가 1·2·4이면 Y 평면 요청도 만든다. 수치 사례의 모드 0은 색차 요청 2개, 모드 2·4는 Y를 포함한 3개였다. 이 모드는 합성 상태로 주입한 내부 값이며 메뉴 이름으로 식별한 값이 아니다. 네 가지 버퍼 전달 사례

요청 조립 0x5AA4E0은 0x010E0001을 제출하고 완료를 기다린다. 장치 쪽 주소 설정은 요청의 +0x1C/+0x28/+0x38을 각각 읽으며 공통 쓰기 0x6E0CBC에서 하위 3비트를 제거한다. 재실행은 정렬된 합성 주소와 가상 레지스터를 사용했다. 모듈 17 수신 함수는 완료 메시지 0x05022001을 보내고, 컨트롤러의 해당 분기는 0x6DBEFC → 0x6DBD0C로 이어진다. 완료 콜백은 재실행했지만 전체 RTOS 큐와 스케줄링은 실행하지 않았다.

4. 마스크 분기에서 JPEG까지의 연결은 미확정이다

초기 CPP 선택의 job+0x20B4 & 0x44가 0이 아니면 job+0x7F=1이 된다. 모듈 17은 이 값이 1일 때 기본 입력과 목적지를 모두 job+0x2354로 바꾼다. 일반 스케일러는 이 디스크립터 대신 job+0x2140을 읽는다. 디스크립터가 다르다는 사실만으로 실제 평면 메모리의 중첩 가능성까지 배제할 수는 없다. 마스크 0x44·두 번째 패스·모드 4 사례

모듈 17 내부에도 기능·설정 검사와 메모리 준비 단계가 있다. 이번 합성 요청 검증은 그 뒤의 디스크립터 읽기·요청 조립 구간에서 시작했다. 따라서 기본 분기의 결론도 “필요 조건이 성립하면 같은 버퍼로 이어진다”는 수준이다. 메뉴 이벤트부터 이 조건들이 모두 만족되는 경로, 중간 레시피 작업이 주소나 내용을 바꾸는지, 마스크 출력이 JPEG 입력으로 재지정되는지는 남아 있다.

5. 검증 방법과 재현 자료

K-3 III의 저장 경로 분석과 조건부 영상 버퍼 분석처럼, 생산자·소비자·분기 조건을 연결하고 원본 명령을 합성 상태에서 다시 실행했다. 주소·테이블·장치 식별값은 K-3 II 이미지에서 별도로 확인했다. 두 기종의 칩이나 주소 체계를 동일하게 취급하지 않았다.

6. 남은 범위

백엔드 B의 대표 쓰기 경로는 SD 명령·ADMA 설정까지 연결했지만 파일 전체의 클러스터 할당·마운트·모든 복구 분기는 남아 있다. CPP 기본 분기는 모듈 17 합성 목적지와 스케일러 입력, 스케일러 목적지와 JPEG 입력의 주소 일치를 확인했다. 실제 촬영 모드의 도달 조건, 마스크 분기의 보조 gate 생산자와 +0x238C 이후 연결은 미확정이다.

실제 RAW 픽셀 처리, JPEG 생성, Exif부터 SD 매체까지의 연속 실행, DMA 데이터 전송과 캐시 일관성은 확인하지 않았다. 정확한 SoC·보조 MCU 부품번호도 기존 미확정 상태를 유지한다. 다음 추적 지점은 보조 gate의 다른 쓰기 지점과 마스크 출력 디스크립터의 재지정, 모듈 17의 선행 기능 검사다.
