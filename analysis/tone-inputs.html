톤 입력의 원본 생산자

이 검증기는 원본 생성자와 recipe 입력 생산자의 8개 재현을 실행합니다. 생성자만 사용하는 1건과 상위 job 필드 15개를 하네스가 공급하는 7건을 구분했습니다. recipe와 문맥의 대상 입력에는 하네스가 직접 값을 쓰지 않습니다. 같은 VM에서 별도로 진입한 소비자가 기존값을 유지하거나 갱신하는지 확인합니다. 실제 촬영 작업의 버퍼 재사용 이력은 검증하지 않았습니다.

생산자재현 결과남은 경계검증 자료

원본 생성자와 recipe 입력 생산자를 연결해 톤 계산에 쓰이는 입력의 출처를 한 단계 더 확인했습니다. 촬영 작업 객체의 recipe는 job+E0C4, 문맥은 job+E608입니다. 이번 재현에서는 recipe의 +92·+A4·+BC·+9C와 문맥의 +8·+A·+C·+E·+60DC·+7A68에 호스트가 직접 값을 쓰지 않았습니다. 대신 원본 생성자를 실행한 뒤 recipe를 갱신하는 원본 명령을 이어 실행했습니다.

화살표는 구분된 실행 구간 사이의 값 전달을 나타냅니다. 4DF834는 같은 VM에서 별도로 진입한 함수이며, 전체 촬영 작업을 연속 실행한 것은 아닙니다.

생성자와 같은 객체의 후속 쓰기

문맥 생성자 859ACC는 네 반워드에 420·256·256·320을 쓰고 +60DC에는 8192, +7A68에는 4096을 씁니다. recipe 생성자 7B1D4C는 +92·+A4·+BC를 0으로, +9C를 8192로 초기화합니다. 이 값들은 생성자 출력입니다. 실제 촬영에서 기본값으로 유지되는지는 확인하지 못했습니다. 이후 처리 분기가 이 반워드들을 다시 쓸 수 있습니다.

659048의 분기는 job+3C와 job+6D를 읽습니다. 어느 한쪽이 0이 아니면 job+264·266·268·26A의 최대 반워드를 10으로 나누고 100을 더합니다. 둘 다 0이면 네 쌍의 합을 각각 16비트로 잘라 그중 최대값을 고릅니다. 784CA0은 이 결과를 recipe+BC에 워드로 씁니다. 이어 7198C4가 job+2080의 바이트를 recipe+A4에 복사합니다.

4DF834는 recipe+A4가 0이면 +BC와 +9C로 문맥의 +7A68·+60DC를 갱신합니다. 0이 아니면 두 값을 유지합니다. 원본 생성자 출력에서 시작한 유지 분기의 계산 결과는 32765였습니다. 이 재현에서는 임의로 넣었던 문맥 입력을 원본 생성자 출력으로 대체했습니다. 실제 촬영 설정값이나 물리적 단위는 확인하지 못했습니다.

근거: 생성자·계산 구간 해시, 생산자 분기, 동일 객체와 정적 추적의 범위. 주소는 파일 오프셋이며 VA = 0x02000000 + 오프셋입니다.

8개 입력 경계 재현

이번 실행은 context+7A74 계산과 getter 4FA83C에서 끝납니다. 톤 곡선 생성은 실행하지 않았습니다.

sum_wrap은 합을 16비트로 자르는 순서를, divide_3c·divide_6d는 두 조건의 대체 관계를 확인합니다. retain_nonboolean은 255도 유지 분기를 고르는지, relocated는 다른 job 주소에서도 같은 계산을 하는지 검사합니다. 준비한 값과 주요 쓰기 명령, 전체 쓰기 건수와 해시는 결과 JSON에 기록했습니다.

재현은 구분된 원본 코드 구간을 실행했습니다. 658EBC의 스택 프레임과 같은 job에서 유도한 포인터는 유지했지만 중간 분류기·서비스 호출은 생략했습니다. 준비한 입력은 상위 job 필드에만 기록했습니다. 모든 실행 명령의 원본 바이트와 허용 쓰기 범위를 검사했습니다. 계산값에는 독립 정수식 검증을 적용했습니다. 일반 실행, 최적화 실행, 독립 검토 실행의 JSON이 바이트 단위로 일치했습니다.

정적으로 연결한 경로와 다음 입력

정적 분석에서는 같은 job+E0C4의 +92를 다시 0으로 쓰는 경로와 +9C를 쓰는 별도 작업 단계도 찾았습니다. +9C 생산자 65EED0은 같은 스택의 임시값을 초기화하거나 조건부로 덮어쓴 뒤 7198D4로 전달합니다. 이 단계는 가상 호출 결과, ROM 표 인덱스, 전역 블록, 구성 서비스의 영향을 받습니다. 이 단계는 정적으로만 추적했으며 관련 서비스를 실행 재현하지 않았습니다. 다른 객체의 같은 오프셋에 쓰는 명령은 같은 생산자로 취급하지 않았습니다.

다음 추적 대상은 job+24C0의 입력 반워드, job+25C와 네 보정 반워드의 생산자, job+2080의 실제 호출 인자와 중간 변경 이력입니다. +9C에서는 전역 블록 4041F420과 구성 서비스 ID 0x42·0x53이 제공하는 값을 먼저 확인해야 합니다. 이 경계가 남아 있어 실제 촬영 작업의 연속 실행, 버퍼 재사용 이력, SuperResolution 메뉴 도달을 이번 결과만으로 확정할 수 없습니다.

근거: 정적 원본 구간 55개의 해시. +9C의 서비스 입력 및 +92 후속 쓰기는 이번 실행 재현의 일부가 아닙니다.

공개 재현 코드와 결과

공개 JSON은 전체 관측의 일치를 확인한 뒤 만듭니다. 먼저 8건의 모든 기록을 타입을 구분하는 JSON으로 직렬화한 뒤 기존 검증 결과의 해시와 대조합니다. 검사를 통과하면 반복 쓰기 기록 133546건을 건수와 순서가 반영된 해시로 줄입니다. 문맥 생성자 쓰기 48건, recipe 생성자 쓰기, 입력 생산자의 저장 명령, 소비자의 조건부 쓰기는 그대로 남깁니다. 원본 명령은 실행할 때마다 바이트를 대조합니다. 입력 파일 전체와 코드 구간의 해시도 검사합니다.

재현 코드는 decoded 파일의 경로를 명시적으로 받습니다. 파일 크기와 전체 SHA-256이 다르면 실행을 거부합니다. 기존 출력 파일이나 그 별칭을 덮어쓰지 않습니다. 공개 자료에는 원본 펌웨어 바이트와 자산이 없습니다. 실행 함수와 소스 목록, 구간 해시, 수치 결과를 제공합니다. 생성자 초기값이 현재 촬영 기본값인지는 확인하지 않았습니다. 정적으로 추적한 후속 생산자와 실제 실행 구간을 구분해서 읽어야 합니다.

전체 비공개 관측 파일은 21,140,898바이트였으며 공개 요약 JSON은 172,506바이트입니다. 요약 전에 검사하는 값은 8건의 모든 관측을 포함한 canonical JSON 해시입니다. 원본 실행 함수는 동일하고, 파일 경로와 소스 캡처를 공개 저장소 구조에 맞췄습니다.

  • 공개 수치 결과 · 검증 범위와 해시
  • 캡처할 소스 목록 · 허용 실행 구간 140개·정적 원본 구간 55개
  • 입출력 경계 시험 · 앞선 문맥·곡선 연결 분석

실행 방법

검증 환경은 Python 3.12.3과 Unicorn 2.1.4입니다. 기존 원본 파일을 보유한 사용자가 별도로 준비한 decoded 파일을 지정합니다. 저장소 루트에서 실행하며 출력에는 새 경로를 사용하십시오. 아래 경로는 예시입니다.

python -B verify_tone_inputs.py /path/to/decoded.bin --output tone-inputs-new.json --compare analysis/tone-inputs.json
python -B -O verify_tone_inputs.py /path/to/decoded.bin --output tone-inputs-opt-new.json --compare analysis/tone-inputs.json
python -B -m unittest discover -s tests -p test_tone_inputs.py

후보 파일을 별도 디렉터리에 둘 때만 --repository에 기존 검증기와 보조 소스가 있는 저장소를 지정합니다. 공개 저장소에 통합한 배치에서는 이 옵션이 필요하지 않습니다. 소스와 입력 검사는 최적화 실행에서도 유지되며, 비교 실패 시 출력 파일을 만들지 않습니다.

입력 SHA-256: 1b87bf35b290e4b4e8910beb4055c34f97504b65e249ad65e5ccc0402bd14cfc

전체 8건 관측 SHA-256: 61e819bd5300c37259b03b31d46b5df225b8cd5ce5636082472f01b7fc55767a

공개 JSON SHA-256: 866e6c071bf48db942a0dbb8ebf931d06edef70c078bafe0d4232945023a1023

분리된 실행 구간의 연결을 검증한 결과입니다. 후속 +92·+9C 생산자는 정적 추적이며, 입력 서비스·작업 스케줄·중간 덮어쓰기·실제 촬영의 버퍼 재사용·SuperResolution 메뉴 도달은 확인하지 않았습니다. 카메라·모터·부팅 동작과 물리적 EV·Q 형식·감마 특성도 이 검증의 범위 밖입니다.

후속 recipe+9C 정수 생산자와 내장 입력 복사에서는 같은 스택 슬롯의 산술·저장 20조건과 별도의 바이트 전달 3조건을 원본으로 대조했습니다. 각 문서의 실행 범위는 구분합니다.
