파일시스템에서 SD·DMA까지
버퍼가 유지되거나 바뀌는 지점

파일시스템 백엔드 하나를 블록 콜백, SD 카드 객체, CMD24·CMD25와 ADMA2 설정까지 연결했다. 전체 섹터는 원래 버퍼 주소를 전달하고, 부분 섹터는 캐시로 복사한 뒤 쓴다. CPP 대체 출력과 JPEG 목적지 공유·재시도 조건도 원본 명령으로 확인했다.

초기 분석앞선 버퍼·메뉴 분석파일시스템섹터 버퍼SD·DMA대체 버퍼검증·재현남은 범위

코드 주소는 해제 이미지의 파일 오프셋이다. 코드 VA는 오프셋 + 0x02000000이며, SD 장치의 0xC6000000 / 0xC7000000은 절대 MMIO 주소다. 도식은 코드 연결과 합성 상태에서 관측한 전달 경로다. 카메라에서 파일을 기록하거나 DMA 전송을 관측한 결과는 아니다.

1. 백엔드 선택부터 카드 객체까지

앞선 Exif 출력 분석은 파일시스템 어댑터 0x6F012C가 버퍼 주소와 길이를 선택된 백엔드로 넘기는 곳까지 추적했다. 후속 분석에서는 초기화 0x76207C가 두 구현을 만들고 파일시스템 객체의 +0xC / +0x10에 등록하는 것을 확인했다. 아래에서는 각각 백엔드 A와 B로 부른다. 이 이름은 분석용 구분이며 파일시스템 종류를 뜻하지 않는다. 생성자·등록·가상 호출 근거

마운트의 비교는 부호 없는 비교다. 경계 직전·일치·직후 세 값을 원본 명령으로 실행해 선택을 확인했다. 비교 대상 card+0x14는 CMD9로 읽은 CSD를 0x5D2C48에서 해석한 512바이트 논리 섹터 수다. 0x758D24 → 0x719768이 이 필드에 결과를 저장한다. 따라서 임계값은 34,493,956,096바이트, 즉 32.125 GiB다. CSD 구조값 0과 1을 넣은 원본 실행으로 단위와 저장 위치를 확인했다. CSD 생산자·실행 근거 두 백엔드의 쓰기 래퍼는 하위 함수가 0 이상의 값을 반환하면 참을 반환한다. 따라서 래퍼의 참 값만으로 요청한 바이트 전부가 기록됐다고 해석할 수 없다. 선택 3건·래퍼 6건

백엔드 A의 정적 호출열은 0xE8A1D8 → 0xEB48A8 → 0xEB4530 → 0xEBEF2C → 0xEBFB30 → 0xEB78BC다. 블록 콜백 0x572970은 초기화 0x572BD4 → 0xE8B570에서 등록된다. 카드 객체는 0x740FA0에서 포트별로 생성되어 0x7413D8로 조회되고, 0x7620E4 → 0x736A4C에서 볼륨 이름과 연결된다. 생성·등록·조회·가상 호출을 따라 연결했다.

2. 전체 섹터와 부분 섹터는 다른 버퍼를 넘긴다

섹터 처리 함수 0xEB78BC와 원본 블록 콜백을 함께 실행했다. 512바이트 섹터를 쓰는 합성 상태에서, 섹터 경계에 맞는 1,024바이트 요청은 소스 포인터를 그대로 카드 쓰기 진입점에 전달했다. 반면 섹터 내부 오프셋 7에 12바이트를 쓰는 요청은 기존 캐시의 해당 구간만 바꾸고 dirty 비트를 설정했다. 이후 원본 flush 함수 0xEB69AC가 캐시 주소로 1개 섹터를 전달했다. 전체·부분 섹터 실행 기록

0xEBB190은 콜백 한 번의 블록 수를 0xFFFF 이하로 나눈다. 65,536개 요청에서는 65,535개와 1개로 나뉘고, 두 번째 소스 주소는 65,535 × 512바이트만큼 증가했다. 파일시스템 검증은 카드 쓰기 진입점에서 멈췄다. 별도 SD 검증에서는 이 65,535개 요청을 원본 카드 루프가 32,768개와 32,767개로 다시 나누는 것을 확인했다. 호스트 생성자가 설정하는 상한 host+0x404 = 0x8000은 16 MiB이며, 64 KiB 설명자 256개와 맞는다. 두 DMA 표 전체, 두 번째 LBA·소스 증가와 명령 레지스터 쓰기를 대조했다. 데이터 자체의 DMA 전송은 수행하지 않았다. write-rechunk-65535 사례 실패 사례에서는 오류 정책을 0으로 대체했으며, 원래 정책에 따른 재시도 전체는 실행하지 않았다.

3. 두 SD 포트의 명령·ADMA2와 완료 통지

포트 설정표 0x9DCFD4의 두 행은 MMIO 기준 주소 0xC6000000과 0xC7000000을 가진다. 초기화는 이 값을 호스트의 컨트롤러 래퍼로 전달한다. 호스트 함수표 VA 0x02A656D0의 쓰기 준비 슬롯 +0x50은 0x56ECB0 → 0x56EBA4, 쓰기 완료 대기 슬롯 +0x54는 0x56ED10이다. 0x56DC14 → 0x56F87C는 port+0x28의 비트 [4:3]에 0b10을 설정하며, ADMA32 선택값과도 맞는다. 두 포트 주소만으로 칩 부품번호나 물리 슬롯의 표기 순서를 확정하지 않는다. 설정표·생성자·함수표

설명자는 little-endian {uint16 속성, uint16 길이, uint32 버퍼 주소}다. 일반 전송의 속성은 0x21, 마지막은 0x23이다. 길이 0은 65,536바이트를 나타낸다. 129블록 사례에서는 소스 주소가 두 번째 설명자에서 정확히 +0x10000 증가했다. 원본 함수는 표 포인터를 port+0x58에 기록한다. 이 단계에서 픽셀이나 JPEG 바이트를 다른 버퍼로 복사하는 동작은 없으며, 실제 DMA에 의한 데이터 이동은 실행하지 않았다. 설명자 바이트 비교 · 64 KiB 길이 인코딩의 외부 대조

주소 인수 함수 0x758138은 카드 +0x37이 2이면 LBA를 그대로, 그 외에는 LBA << 9를 보낸다. 이는 블록 주소와 바이트 주소를 사용하는 SD 카드의 구분과 맞는다. 명령 번호의 의미는 공개 MMC 명령 정의와 대조했다. 여기서 카드 값 2의 전체 열거형이나 모든 카드 초기화 분기까지 확정한 것은 아니다.

명령 대기 실패, 카드 응답 오류, ADMA 오류, 전송 대기 실패, 명령 금지 상태를 각각 주입한 5개 사례에서 원본 하위 함수는 실패를 반환했다. 별도 IRQ 사례에서는 상태 0x02008003으로부터 0x8003과 0x02000000을 같은 이벤트 객체에 게시하고 두 W1C 값을 기록했다. 합성 MMIO는 장치의 실제 타이밍이나 W1C 하드웨어 동작을 재현하지 않는다. 또한 수치 실행은 카드 상위 함수의 범위 검사·복구 분기를 지난 하위 명령 함수 또는 블록 분할 루프에서 시작했다. CMD9 두 사례는 카드 CSD 조회 함수에서 시작해 실제 응답 레지스터 읽기와 용량 저장까지 실행했다.

4. CPP와 JPEG의 대체 버퍼 조건

CPP의 초기 주소 선택과 두 번째 패스는 서로 다른 제어값을 사용한다. 0x659790의 job+0x20B4 & 0x44가 0이면 직접 평면 +0x160/+0x164/+0x168을 쓴다. 0이 아니면 job+0x2354의 디스크립터를 읽는다. 이 디스크립터를 채우는 생성 조건 job+0x20B2 == 1도 별개다. 두 조건을 독립적으로 바꾼 합성 사례를 포함해 검증했다. 생산자·소비자·실행 조건

두 번째 평면 디스크립터는 슬롯 13의 0x654354에서 계산된다. 주소를 32바이트 단위로 올리고, 가로·세로 곱과 그 절반, 패딩 값을 이용해 세 평면을 배치한다. 일반 스케일러 입력은 여전히 0x659AC8…0x659AE8에서 직접 평면 필드를 읽는다. 따라서 대체 CPP 출력이 JPEG 모듈 16의 입력과 같은 메모리를 가리키는지는 확인되지 않았다. 처리 gate를 0으로 넣은 사례는 방어 분기를 확인하기 위한 주입이며 일반 작업 생성자의 상태를 관측한 결과가 아니다.

5. 검증 범위와 재현

K-3 III의 저장 장치 분석처럼 설정표·호출·레지스터를 연결하고, 원본 명령에 합성 상태를 주입해 정상·오류 분기를 확인했다. K-3 III의 주소나 칩 정보를 가져오지 않았다. 입력은 기존 보고서와 같은 해제 이미지이며 SHA-256은 1b87bf35b290e4b4e8910beb4055c34f97504b65e249ad65e5ccc0402bd14cfc다.

6. 다음에 확인할 연결

백엔드 B의 파일 쓰기 이후 블록 콜백, 실제 파일 할당·클러스터 체인, 카드 상위 함수의 범위 검사·재시도·복구 경로 전체는 남아 있다. 대체 CPP 출력에서 스케일러·JPEG 입력으로 넘어가는 주소 관계와 실제 촬영 모드의 분기 선택도 추가 확인이 필요하다. CPU 주소와 DMA 버스 주소의 관계, 캐시 일관성, 전송 타이밍과 물리 SD 기록은 이번 합성 실행으로 입증할 수 없다.

정확한 SoC·보조 MCU 부품번호, 전체 RAW→JPEG의 물리 픽셀 전달 함수, 실기 촬영·플래싱은 검증하지 않았다. 공개 저장소에는 직접 작성한 도구, 관찰값, 도식과 문서만 포함한다. 제조사 펌웨어와 전체 디스어셈블은 공개하지 않는다.
