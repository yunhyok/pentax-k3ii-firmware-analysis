1. 공식 대응표의 공통 항목을 분석 대상으로 삼았다

Ricoh의 K-3 III·K-3 II 메뉴 대비표 첫 페이지는 K-3 II의 촬영 메뉴 1·정지화상 기록 설정에 있는 RAW 파일 형식을 K-3 III의 촬영 메뉴 5·RAW 파일 형식과 대응시킨다. 이는 기능 대응의 근거다. 이벤트 번호나 실행 코드 호환성의 근거로 사용하지 않았다. 제조사 메뉴 대비표 · 공식 안내

2. 선택과 적용은 서로 다른 단계다

상위 항목 0x0150000A의 적용 이벤트 0, 1, 6, 0x10, 0x11, 0x1D, 0x20에서 임시값을 저장한다. 이벤트 3과 0xF는 저장하지 않고 임시값을 복원했다. 다른 상위 항목 ID를 주면 설정은 바뀌지 않고 임시 선택이 남았다. 이 번호를 물리 버튼 이름으로 해석하지 않았다. 선택·이탈·적용 사례 12건

설정 쓰기는 0x6DA5E4 → 0x6F1A38 → 0x700E84 → 0x6FE52C로 이어진다. 활성 인덱스 0…7의 저장 뱅크는 [0, 0, 2, 3, 4, 5, 6, 7]이다. 인덱스 0과 1은 뱅크 0을 공유한다. 검증에서는 선택된 뱅크와 미러의 변경을 확인하고 다른 뱅크의 표식값이 그대로 남는지도 대조했다. 영구 저장 매체 기록은 이 범위에 포함하지 않았다. 원본 설정 getter·setter와 뱅크 검사

역방향 함수 0x3E53A4는 저장값 0을 PEF 위젯, 1을 DNG 위젯으로 바꾼다. 대조값 2에서는 일치하는 위젯이 없다는 값 0을 반환했다. 이 결과는 앞선 Pixel Shift 분석처럼 문자열·화면 이벤트·설정값을 별도로 검증한 것이다.

3. 텍스트 준비 ABI까지 확인했다

각 리소스에서 언어 인덱스 0, 비어 있는 1바이트 소스인 9, 16비트 소스인 10, 활성 인덱스 10에서 인덱스 0을 강제한 경우를 실행했다. 총 12건의 출력 바이트와 길이를 대조했다. 영문 라벨은 저장 글리프 코드에 0x1E를 더하면 읽을 수 있지만, 전체 글리프를 Unicode나 UTF-16 텍스트라고 단정하지 않았다. 폰트 아틀라스와 LCD 비트맵은 추출하지 않았다. 텍스트 사례와 출력 해시
