1. 분석 대상과 동일성

2. 파일 구조와 난독화 해제

이 파일은 0x80바이트 블록 단위의 32비트 little-endian XOR 방식으로 난독화되어 있다. 두 헤더에서 얻은 초기값으로 세 구간을 해제했다. 결과의 길이와 파일 오프셋은 원본과 같다. 이번 단계에서는 압축 해제가 필요하지 않았다. 해제된 내부 구간에 다른 압축 데이터가 존재하는지는 별도 조사 대상이다.

0x01000000부터 파일 끝까지는 61,440바이트다. 이 구간에는 별도 초기값과 PENTAX K-3MC 헤더가 있다. 독립된 해제 구간이라는 사실은 확인했지만 담당 기능과 명령어 집합은 미확정이다. 이름의 MC만으로 기계 제어용 프로세서라고 단정하지 않는다.

해제 전후 길이가 같고 기존 디코더와 모든 바이트가 일치했다. 이 파일에 적용한 분기는 압축 해제를 호출하지 않는다. 독립 구현 대조 결과 · Python 검사기

3. Cortex-A9를 구분하는 시작 경로

파일 시작의 ARM 예외 벡터와 리셋 대상 포인터를 대조하면 주 이미지의 기준 주소 후보는 0x02000000이다. 리셋 대상은 0x02000200이며, 이 위치의 코드에서 MIDR를 읽고 0xFFF0으로 마스킹한 뒤 0xC090과 비교한다. Arm 문서에서 MIDR의 부품 번호 0xC09는 Cortex-A9다. 따라서 펌웨어에 Cortex-A9를 구분하는 시작 경로가 있다는 해석을 지지한다. 실제 카메라에서 MIDR를 읽은 것은 아니며 SoC 부품번호, 코어 수, 동작 클럭은 이 검사로 알 수 없다.

근거: MIDR 검사 오프셋·해시 · 명령어·포인터 검증 · Arm Cortex-A9 TRM §4.3.1

리셋 포인터만으로 주소를 확정하지 않았다. 마스크·비교값을 가리키는 두 포인터, 예외 처리기 진입점, HDMI 문자열을 가리키는 네 데이터 포인터를 대조했다. 모두 같은 주소 변환과 맞는지 확인했다. 이 결과는 분석용 기준 주소를 뒷받침하지만 실행 중의 전체 메모리 배치나 재배치 구간을 설명하지는 않는다.

4. 후속 추적을 위한 문자열 근거

T-Kernel과 T-Kernel/OS 진단 문자열을 찾았다. RAW 현상, 톤·감마, AF 디포커스와 관련된 문자열도 후속 코드 추적의 출발점으로 기록했다. 문자열의 존재만으로 함수의 실행, 알고리즘의 의미, 카메라 메뉴와의 연결을 확정하지 않는다. 길이 6 이상인 인쇄 가능한 ASCII 연속 구간은 30,254개이며 기계어에서 우연히 생긴 구간도 포함할 수 있다.

5. K-3 Mark III와 구분할 점

리코는 K-3 II의 영상 엔진을 PRIME III, K-3 Mark III를 PRIME V와 2세대 가속기로 설명한다. 기존 K-3 III 분석에서는 Linux 장치 트리의 SC2000A·Cortex-A7 정보를 확인했다. 이번 K-3 II 분석의 Cortex-A9 비교 경로와 파일 구조는 별도로 검증한 결과다. 두 모델의 하드웨어 주소와 영상처리 동작이 호환된다고 볼 근거는 없다.

6. 재현과 검증 범위

REA로 공식 ZIP의 구성원과 해시를 확인했다. Windows 환경에서는 REA의 Linux 전용 Binwalk 스캐너를 실행할 수 없었고, 원시 ARM 이미지를 처리할 네이티브 디컴파일 공급자도 준비되어 있지 않았다. 난독화 해제와 근거 검사는 Python, 시작 코드 판독은 Capstone으로 수행했다. 이 도구의 결과를 REA가 생성한 코드 분석 증거로 표시하지 않았다.

기본 분석은 Python 3.12의 표준 라이브러리만 사용한다. 엔트로피 그림은 선택적으로 matplotlib 3.9.2를 준비한 뒤 python render_entropy.py로 다시 만들 수 있다. 먼저 원본을 별도로 준비한다. 출력 디렉터리는 새 경로여야 하며 기존 파일을 덮어쓰지 않는다.

이어갈 분석

다음 단계에서는 데이터 복사 구간과 RAM 재배치를 추적하고 T-Kernel 호출·명령 처리 구조를 확인한다. 이어 RAW 현상과 톤·감마 진단 문자열의 참조를 실제 코드에 연결한다. 보조 이미지의 명령어 집합과 부품 정보는 주 이미지와 분리해 조사한다. 이번 공개분은 분석을 재현하고 이어갈 수 있도록 만든 초기 조사 결과다.

7. 출처와 공개 범위

공개 저장소에는 직접 작성한 분석·검증 도구, 관찰값, 도식과 HTML 문서를 포함한다. 원본 펌웨어, 해제 바이너리, 전체 문자열 덤프와 디스어셈블 결과는 로컬에 보관한다. 카메라 플래싱, 실기 실행, 전체 펌웨어 재빌드는 수행하지 않았다. 도구의 GPL-2.0 라이선스는 제조사 펌웨어에 적용되지 않는다.

난독화 해제 로직은 Tao Wang의 pentax-firmware-tool을 바탕으로 구현했다. 원 프로젝트는 MooseV2·svenpeter42의 작업과 bootcoder의 패치를 출처로 밝힌다. 도구와 본 저장소에는 GPL-2.0을 적용하며 원본 펌웨어의 권리는 제조사에 있다.

리코 배포 페이지에 펌웨어 사용 조건이 있다. 이 문서는 해당 조건의 법적 효력을 판단하지 않으며, 공개 저장소에 제조사 펌웨어를 재배포하지 않는다.
